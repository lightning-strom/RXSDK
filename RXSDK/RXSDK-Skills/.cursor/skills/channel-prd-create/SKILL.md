# RXSDK 渠道 PRD 创建规范

## 适用场景

当用户要求创建、补全或调整 RXSDK 新渠道接入 PRD 时使用本规范。默认模板为 `RXSDK-Doc/prd/template.md`。

## 表单式收集流程

创建新渠道时，必须先用问答方式收集信息，再生成 PRD。优先用 `AskQuestion` 做选择题；无法用选择题表达的信息，再用普通消息请用户补充。

### 选择题

一次性询问以下选择项：

- 接入功能（多选）：登录、支付、分享、实名、数据上报、其他。
- 渠道区域（单选）：国内渠道、海外渠道、待确认。
- 支持平台（多选）：Android、iOS、小游戏、待确认。
- 测试环境参数类型（多选）：appId、gameId、merchantId、clientId、apikey/secret、证书、回调地址、包名/Bundle ID/AppID、其他。

### 文本补充

选择题完成后，继续请用户补充以下自由文本：

- 官方文档地址、附件路径或文档摘要。
- 测试环境参数的具体参数名、参数值和用途说明。
- 登录参数：后台登录方式名称、`type`、SDK `method`、配置项、`ext` 新增字段、回调字段。
- 支付参数：后台支付方式名称、`type`、SDK `pay_type`、配置项、`ext` 新增字段、支付回调或验单要求。
- 需求说明：本次接入背景、业务目标、特殊限制或验收重点。

如果用户只提供渠道名称，先提问，不要直接创建完整 PRD；用户明确要求“先建空文档”时，才用占位项落盘。

## 必须先收集的信息

如果用户未提供以下信息，先询问或在文档中标记为待确认，不要臆造：

- 官方文档：URL、附件路径或关键章节摘要。
- 接入功能：登录、支付、分享或其他能力。
- 渠道区域：企业管理后台下的国内渠道或海外渠道。
- 接入平台：Android、iOS、小游戏，可多选。
- 需求说明：接入背景、业务目标、限制条件和验收重点。
- 登录参数：后台登录方式名称、`type`、SDK `method`、配置项、`ext` 新增字段、回调字段。
- 支付参数：后台支付方式名称、`type`、SDK `pay_type`、配置项、`ext` 新增字段、支付回调或验单要求。
- 渠道环境：测试参数、平台包名/Bundle ID/AppID、瑞雪环境 `cpid`、`channelid`、`productid`、`baseUrl`。

## 工作流程

1. 读取 `RXSDK-Doc/prd/template.md`，沿用模板章节和术语。
2. 先执行“表单式收集流程”，得到用户选择和文本补充。
3. 按用户提供资料填写 PRD；缺失项保留 `[创建新渠道时提供]` 或写入“待确认事项”。
4. 只生成用户选择的接入功能；未选择的功能不要显示“否”或“不涉及”。
5. 只生成用户选择的平台小节；未选择的 Android、iOS、小游戏不要显示。
6. 渠道测试环境只生成用户在问卷中选择的参数类型；未选择的参数类型不要显示。
7. 对已选择的登录或支付分别明确后台配置、SDK 入参、`ext` 字段和回调要求。
8. 敏感信息只记录参数名、用途和注入方式；不要写入生产密钥、token、apikey 明文。
9. 若用户要求落盘，优先保存为 `RXSDK-Doc/prd/[channel-key].md`，其中 `[channel-key]` 使用小写英文渠道标识。

## 输出要求

- 文档标题使用 `# [渠道名称] 接入 PRD`。
- 后台 `type`、SDK `method`、SDK `pay_type` 使用代码格式；表格内容中的渠道标识不使用反引号。
- 表格必须使用飞书兼容的标准 Markdown 表格，禁止使用 HTML `<table>`、`<tr>`、`style` 等写法。
- 表格第一行表头使用反引号，不使用 `**`，例如 ``| `项目` | `内容` |``；灰色背景由飞书表格表头样式承载，不在 Markdown 中写 CSS。
- 参数表保留“参数 / 值 / 说明”结构。
- 使用 `- 字段名：内容` 形式的列表时，字段名必须加粗，例如 `- **包名**：...`。
- 平台包名未提供时使用默认值：Android 为 `com.ruixue.sdkdemo`，iOS 为 `com.ruixue.sdkpublic`。
- “接入功能”只列需要接入的功能，不展示未接入功能。
- “渠道测试环境”只列问卷选择的参数类型，不额外推断和展开未选择参数。
- “平台接入信息”只列需要支持的平台，不展示未接入平台。
- “功能开发”只包含已选择功能的后台配置和 SDK 参数。
- 新建 PRD 时填写“需求创建日期”和“最后修改日期”；修改已有 PRD 时只更新“最后修改日期”。
- 需求说明必须独立成段，不要只写在备注里。
- 不生成“验收标准”和“待确认事项”章节；缺失信息在对应小节中用 `[待补充]` 标记。
