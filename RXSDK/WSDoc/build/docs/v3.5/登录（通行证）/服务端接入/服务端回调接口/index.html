服务端回调接口

封停用户​

使用运营【违规封号处理】、法务【违规举报管理】，封停用户时会调用此接口

类型：同步 Action: user-ban 认证方式： CPSign

请求参数 []User​

User结构

字段类型是否必填说明
open_idString是望舒OpenID
user_idString是用户的ID
daysInt是封停的天数,0为永久封停;如不为0则用当前时间加上天数
causeString是封停的原因
titleString否通知标题
contentString否通知内容
cp_user_idString是cp游戏id

请求示例​

[
  {
    "open_id": "xxx",
    "user_id": "user_123",
    "days": 1,
    "cause": "封停原因"
    "title": "奖励提示的标题",
    "content": "奖励提示的内容"
  },
  {
    "open_id": "xxx",
    "user_id": "user_123",
    "days": 1,
    "cause": "封停原因"
    "title": "奖励提示的标题",
    "content": "奖励提示的内容"
  }
]

返回示例​

{
  "code": 0
}

响应要求​

字段类型说明
codeNumber0成功
msgString错误信息
dataAny需要返回数据时放到此字段

绑定望舒账号接口 已下线​

类型：同步 Action: account-bind 认证方式： CPSign

请求参数​

字段类型是否必填说明
credential_typestring否账号类型，与上一节 "查询游戏账号信息接口" 中的 cerdential_type 参数相同。
identifierIdentifier否此为 "查询游戏账号信息接口" 接口返回的 identifier 信息。
rxinfoRxinfo否望舒账号标识信息。

对于接入过旧望舒的项目，其 identifier 由新望舒直接从旧望舒查询，CP 方无需实现 account-query 接口。 新望舒调用 account-bind 接口时，传递的 identifier 字段结构如下

Identifier​
字段类型说明
idint64旧望舒用户 ID。
openidstring旧望舒 openid。
rxversionint64旧望舒数据版本：
null，0 表示望舒 1.0 的账号；
1 表示望舒 2.0 或 3.0 的账号；
Rxinfo​
字段类型说明
openidstring望舒 openid。

请求示例​

当望舒调用 CP 的 account-query 接口查询到用户名为 "rssllyn" 的旧账号信息时，望舒将会使用该旧账号信息创建对应的望舒账号，生成望舒 OpenID，并调用以下 account-bind 接口通知 CP 游戏服务器，将该旧账号绑定与对应的望舒账号（通过望舒 OpenID 标识）绑定。

{
  "credential_type": "username",
  "identifier": 5,
  "rxinfo": {
    "openid": "rxuBQtC2oRgb6Dytk43C0lHXA=="
  }
}

返回示例​

{
  "code": 0,
  "data": {
    "userid": 1
  }
}

响应要求​

字段类型说明
codeNumber0成功
msgString错误信息
dataData需要返回数据时放到此字段
Data​

对于接入过旧望舒的项目，由于前述"查询游戏账号信息接口"是在望舒内部查询旧望舒数据完成的，而其中的 userid 信息在旧望舒系统中没有存储，因此需要在此处返回。另外，在这种情况下会出现同一个旧望舒账号会生成多个新望舒账号，对应调用多次本接口，每次传递的新望舒 openid 不同，CP 方实现本接口时需要注意予以支持。

字段类型说明
useridnumberCP 方的游戏用户ID。

查询并绑定望舒账号接口 已下线​

类型：同步 Action: account-queryandbind 认证方式： CPSign

请求参数​

字段类型是否必填说明
credential_typestring是账号类型，对应通行证登录接口中的 [method](/docs/v3.5/登录（通行证）/服务端接入/服务端 API)参数，但是当 method 为 "username" 时，根据用户名不同，credential_type 可以分为 "username", "phone", "email" 三种。
credential_paramsobject是与 credential_type 对应的账号信息，旨在涵盖各游戏可能用于构造用于名的所有账号信息。
migrate_args任意合法的 json 类型, 比如 string, number, array, object否客户端调用通行证接口时传的 migrate_args 参数, 在此处透传给 CP. 有可能触发调用 account-queryandbind 的通行证接口, 都支持传递此参数.
rxinforxinfo是望舒账号标识信息。
rxinfo结构​
字段类型说明
openidstring望舒 openid。
cp_useridint64如果当前望舒用户是通过之前的账号迁移操作从 CP 方导入的，则 cp_userid 会带上之前账号迁移 account-query 接口返回的 info.userid 信息。
CP 接口应判断当前迁移账号与 cp_userid 是否不同，如果不同，则不应绑定，防止两个 user 有相同的 openid，除此之外，还应该返回当前账号的包括 userid 在内的信息，以便望舒判断两个 userid 不匹配而禁止用户操作。当然，本接口也可直接返回错误，但 CP 客户端得对应处理通过望舒转发到客户端的错误信息。

请求示例​

当用户初次登录一个微信小游戏账号时，望舒账号系统中找不到对应的账号信息，会先创建望舒账号，生成望舒 OpenID，然后调用 account-queryandbind 接口查询是否存在旧账号，如果存在则将其绑定到望舒账号（通过望舒 OpenID 关联）并返回旧账号信息，如果有查询到旧账号信息，望舒将用返回的用户信息修改望舒用户，实现导入。

{
  "credential_type": "minigame",
  "credential_params": {
    "openid": "oD7-Z5amE_5wgGL19xxVqX3PpYrI",
    "unionid": "oPXyfuLlc8JkrDKNy9xa86StszUA"
  },
  "rxinfo": {
    "openid": "rxuW1CZqRJt22uL/g4YUAR6Ow=="
  }
}

返回示例​

{"code": 0  }

响应要求​

字段类型说明
codeNumber0成功
msgString错误信息
datadata需要返回数据时放到此字段
data结构​
字段类型说明
infoobject账号数据

info 数据接口，参考 "查询游戏账号信息接口" 接口对返回数据结构的说明。

由于这个接口相当于时前面两个接口的合并，省掉了中间过程，因此我们可以看到请求参数和返回数据结构中都没有 identifier 字段信息。

查询游戏账号信息接口 已下线​

类型：同步 Action: account-query 认证方式： CPSign

请求参数​

参数类型备注
credential_typestring账号类型。
credential_paramsobject与 credential_type 对应的账号信息，旨在涵盖各游戏可能用于构造用于名的所有账号信息。
migrate_args任意合法的 json 类型, 比如 string, number, array, object客户端调用通行证接口时传的 migrate_args 参数, 在此处透传给 CP. 有可能触发调用 account-query 的通行证接口, 都支持传递此参数.

每种 credential_type 及其对应的 credential_params 结构如下。默认情况下，望舒对下列各种账号类型都会在用户进行相关账号操作时尝试调用 CP 账号迁移接口，如果需要禁用部分账号类型，请联系望舒进行修改。

guest​
参数类型备注
idfastring仅用于 iOS 设备。目前 iOS 系统主流的广告获取设备标识符方式。用户可开启、关闭，每次切换会改变为新的取值。10 以下的版本关闭时也能取到唯一值, >=10 的 iOS 版本关闭时取到的值为 00000000000 ；系统大版本升级（如 11 到 12） IDFA 也会发生变化。
android_idstring仅用于 Android 设备。Android 版本 = 8.0，应用签名、用户（即系统上的用户账号）和设备的每个组合都具有唯一的 ANDROID_ID 值，即使系统升级也不变。
imeistring仅用于 Android 设备。Android 版本 < 6.0，只需要 READ_PHONE_STATE 静态权限（安装 App 时即可获取到该权限），即可通过系统 API TelephonyManager#getDeviceId API 获取准确值；6.0 <= Android 版本 <= 9.0，READ_PHONE_STATE 升级为动态权限，安装 App 时不会获得该权限，需要在 App 运行时用户在弹窗确认授权后才可以获取；Android 版本 >= 10.0，设备不可变 ID 的隐私保护得到进一步升级，需要 READ_PRIVILEGED_PHONE_STATE 权限才可以获取 IMEI，而该权限只有系统级别的应用才可以获得，因此一般 App 无法获取到 IMEI。
oaidstring仅用于 Android 设备。移动安全联盟（简称 MSA）制定的匿名设备标识符。可用于 android 系统的补充设备标示，通常 android10 以上的国内主流设备都可以获取。具体 OAID 介绍以及最新覆盖厂商范围请详见 MSA 官网：http://msa-alliance.cn。
macstring仅用于 Android 设备。设备 Mac 地址。
device_codestring望舒根据以上设备信息生成的设备码，或是游戏客户端自定义的设备码。

请求示例

{
  "credential_type": "guest",
  "credential_params": {
    "device_code": "c97b107060054f01bd57e9511d0ca497"
  }
}

响应结构​
