快速开始

v3.5 归档文档

此页为 v3.5 归档文档。新项目请查看 v4.x 对应文档。

提示

区服项目必接：区服接入参考。

准备工作​

请登录望舒系统初始化相关服务，如果还没有望舒账号请查看准备工作说明。 望舒系统地址，可登录企业管理后台 > 已部署项目中查看。

环境要求​

  • iOS 12 或更高版本

隐私权限​

提示

SDK 会获取一些设备相关信息，有些信息会涉及到隐私权限。 部分渠道审核会有限制，请注意相关配置，并在审核模式下进行相关处理。

获取的相关信息不违反苹果审核条例，但要注意提审时的相关信息是否配置正确。

  • 设备相关：（设备启动时间、国家、语言、设备名称、系统版本、设备 Machine、运营商、物理内存容量、硬盘内存容量、系统更新时间、设备 Model、设备时区、设备 mnt_id、设备初始化时间）生成 caid。
  • 隐私相关：获取剪贴板内容、获取 IDFA、接入了定位功能需要获取定位权限。

用途​

名称备注
设备码设备唯一标识，用于生成游客账号、大数据筛选条件
oaid/caid广告标识，用于媒体平台投放归因

我们如何使用 Cookie 和同类技术​

登录前使用客服功能会随机生成了一个字符串用于标识匿名用户，以便该匿名用户下次再使用客服时获取之前的聊天记录。

SDK 集成​

自动化集成（推荐）​

  1. 在终端窗口中输入以下命令，安装 CocoaPods。
sudo gem install cocoapods
  1. 进入项目所在路径，在终端窗口中输入以下命令，创建 Podfile 文件。
pod init
  1. 编辑 Podfile 文件，添加 pod 'RXSDK_Pure'
pod 'RXSDK_Pure'
  1. 在终端窗口中输入以下命令。pod 命令执行完成后，会生成集成了的 SDK 的 .xcworkspace 后缀的工程文件，双击打开即可更新并安装 SDK。
pod install

更新执行 pod update

pod update

工程配置​

请求添加权限

Info.plist 添加获取 IDFA 权限 Privacy - Tracking Usage Description 此标识符将用于向您推送个性化广告。

关闭 Bitcode。

由于 SDK 不支持 Bitcode，所以需要在工程中关闭 Bitcode 选项，将 Enable Bitcode 置为 NO 状态即可。

添加 Framework

  • 在 TARGETS > Project Name > General > Frameworks, Libraries, and Embedded Content 菜单，点击 +，将 AuthenticationServices 添加。

注：引用到 RXSDK_Pure.framework 的 target 都需要添加，否则会引起闪退问题。

  • 在 TARGETS > Build Phases > Link Binary With Libraries 中将 Status 设置为 Optional。

创建一个 swift 文件，否则会引起闪退。

SDK 初始化（必须）​

::: tip 初始化 SDK 时需传入 productId、channelId、cpid、baseUrlList 参数信息。

  • productId、channelId 在望舒游戏发行平台获取（创建产品或渠道），查看使用说明。
  • cpid、baseUrlList 在望舒企业管理后台获取（创建项目），查看使用说明。
  • 初始化为异步调用，失败将不能使用 SDK 功能，请注意处理调用逻辑。 :::

接口原型

/**
 * 初始化SDK
 * 初始化后会 SDK 会自动激活
 * @param config 初始化配置
 */
- (void)initWithConfig:(RXSdkInitConfig *)config
              complete:(RequestComplete)complete;

RXSdkInitConfig 参数说明​

字段类型是否必填备注
productIdNSString是产品 id
channelIdNSString是渠道 id
cpidNSString是cpid
baseUrlListNSArray是请求域名队列
completeBlock是回调函数
launchOptionsNSDictionary是启动参数，- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions 中的 launchOptions
isLogEnableNSString否日志开关，debug默认开启，release默认关闭
usePrivacyBOOL否首次启动是否展示用户隐私授权页面，YES展示，NO不展示，默认NO不展示
agreementMapNSMutableDictionary否自定义协议键值对，key:00001（00001为示例，实际值是望舒协议key）或链接 value:《用户协议》
agreementTitleNSString否协议标题，默认为 “用户协议和隐私政策”
isUseDNSBOOL否是否打开 DNS，YES 打开，NO 关闭，默认为 NO，需配合阿里DNS SDK或腾讯 DNS SDK使用
openRacingBOOL否是否开启竞速，YES 开启 NO 关闭，默认 NO，详情查看openRacing 说明

openRacing 说明​

baseUrlList 数量为 1 时 不生效。 开启竞速模式：当 baseUrlList 有多个时，根据网络请求响应速度对数组进行排序，后续 SDK 内部网络请求根据排序后的数组使用对应域名。 关闭竞速模式：当 baseUrlList 有多个时，SDK 内部网络请求根据数组顺序使用对应域名。

complete 说明​

SDK 中使用的 complete 为通用结构，成功返回 response 不返回 error，失败不返回 response 返回 error。

  • response 数据结构参照具体使用的 Api 响应结构；
  • RX_CommonRequestError 中包含 error（http 原始错误信息） 和 responesObject（望舒包装后的错误数据），正常使用中只需处理 responesObject 数据即可，responesObject 无返回数据时可通过 error 获取 iOS 原始错误信息排查问题；

调用示例

RXSdkInitConfig *config = [[RXSdkInitConfig alloc] init];
config.productId = @"your product id";
config.channelId = @"your channelid id";
config.cpId = @"your cpid id";
config.baseUrlList = @[@"https://xxx"];
[[RXService sharedSDK] initWithConfig:config complete:^(NSDictionary * _Nullable response, RX_CommonRequestError * _Nullable error) {
        if (!error) {
            NSLog(@"初始化成功");
        } else {
            NSLog(@"初始化失败");
        }
}];

接入功能​

SDK 提供了众多功能。请在初始化 SDK 后，根据项目需要，参考相应功能的文档，接入相应功能。 绝大多数游戏都会接入望舒登录，所以我们推荐从这一功能开始。

自定义接口请求​

::: info 强烈建议 项目组实现该接口，可以处理一些紧急的线上事故（不依赖发版）。 :::

接口原型

/**
 * 自定义请求
 * @param url 接口名
 * @param header 请求头
 * @param body 请求参数
 * @param method 请求类型  1 Post请求，2 Get请求，默认Post
 * @param needLogin 接口是否需要登录，不需要登录则请求头中的ruixue-accesstoken会被清空
 */
- (void)createRequestWithUrl:(NSString *)url
                      header:(NSMutableDictionary * _Nullable)header
                        body:(NSMutableDictionary * _Nullable)body
                      method:(NSInteger)method
                   needLogin:(BOOL)needLogin
                    complete:(void(^)(NSDictionary *response, RX_CommonRequestError *error))complete;

参数说明​

字段类型是否必填备注
urlNSString是api 请求地址
headerNSString否请求头，不传默认传入望舒请求头
bodyNSString否请求参数
methodNSString否请求类型 1 Post 请求，2 Get 请求，默认 Post
needLoginNSArray否接口是否需要登录，不需要登录则请求头中的 ruixue-accesstoken 会被清空

调用示例

NSMutableDictionary *header = [NSMutableDictionary dictionary];
    NSMutableDictionary *body = [NSMutableDictionary dictionary];
    [[RXService sharedSDK] createRequestWithUrl:url header:header body:body method:2 needLogin:NO complete:^(NSDictionary * _Nonnull response, RX_CommonRequestError * _Nonnull error) {

    }];

设置语言​

客户端可设置 SDK 语言。

提示

海外项目需要根据发行地区或 App 的语言进行设置，避免出现 SDK 的文案和 App 内语言不一致的情况。

接口原型

/**
 * 设置当前语言
 * @param language  语言需符合标准格式
 */
- (void)setLanguage:(NSString *)language;

调用示例

[[RXService sharedSDK] setLanguage:@"zh"];

设置地区​

客户端可设置 SDK 地区,设置后自动在请求头添加 ruixue-area 传给服务器。

提示

海外项目需要根据发行地区进行设置，查看 地区码，默认获取系统设置地区。

接口原型

/**
 * 设置当前地区
 * @param area 地区码
 */
- (void)setArea:(NSString *)area;

调用示例

[[RXService sharedSDK] setArea:@"CN"];

设置自定义错误消息提示​

提示

规则 1：根据设置的错误码直接读取对应提示替换 msg；

规则 2：如果设置中有 default 的 key，将未配置的错误码 msg 统一替换为 default 的 value； 规则 3：$code$ $msg$ $thirdcode$ $thirdmsg$ 为模板占位符，使用后将分别被替换为sdk接口默认返回code msg thirdcode thirdmsg

以上规则仅适用于调用了 - (void)configErrorMsg:(NSDictionary )msgDic 方法，未调用此方法，则返回sdk默认提示信息，映射键值对中key 对应 value 不能为空字符串，否则该对映射不生效

接口原型

/**
 * 设置自定义错误码信息
 * @param msgDic 设置自定义错误码的字典
 */
- (void)configErrorMsg:(NSDictionary *)msgDic;

数据结构 错误码设置的参数形式，应按照语言进行分类设置，无需将提示的语言类型配置齐全，为方便未来扩展语言结构，设置的数据结构例如：

{
    en:{
            "3001":"error1",
            "3002":"error2"
        }
    zh:{
            "3001":"错误1",
            "3002":"错误2"
    }
}

调用示例

NSMutableDictionary *zhDic = [mDic objectForKey:@"zh"];
[enDic setObject:@"错误码信息1" forKey:@"3001"];
[enDic setObject:@"错误码信息2" forKey:@"3002"];
[enDic setObject:@"错误码信息3" forKey:@"3100"];
[enDic setObject:@"错误码信息4" forKey:@"3101"];
[enDic setObject:@"错误码信息5" forKey:@"3102"];
[enDic setObject:@"默认错误 $code$ $thirdcode$ $thirdmsg$" forKey:@"default"];

NSMutableDictionary *enDic = [mDic objectForKey:@"en"];
[enDic setObject:@"error1" forKey:@"3001"];
[enDic setObject:@"error2" forKey:@"3002"];
[enDic setObject:@"error3" forKey:@"3100"];
[enDic setObject:@"error4" forKey:@"3101"];
[enDic setObject:@"error5" forKey:@"3102"];
[enDic setObject:@"error $code$ $thirdcode$ $thirdmsg$" forKey:@"default"];

NSMutableDictionary *mDic = [NSMutableDictionary dictionary];
[mDic setObject:zhDic forKey:@"zh"]
[mDic setObject:enDic forKey:@"en"]

[[RXService sharedSDK] configErrorMsg:mDic];

全局通用回调​

提示

一些需要特定条件触发的事件会通过全局通用回调将事件通知给客户端，通过回调的 type 区分事件类型，并处理相应的业务逻辑。

在需要接收回调的类中添加RXPublicDelegate，并指定代理接收对象[RXService sharedSDK].publicDelegate = self;，实现代理方法。

接口原型

/**
 * 全局通用回调
 * @param type 回调类型
 * @param response 回调数据
 */
- (void)rxPublicCallback:(NSInteger)type response:(NSDictionary *)response;

调用示例

- (void)rxPublicCallback:(NSInteger)type response:(NSDictionary *)response
{
    // 上报反馈日志
    if (type == feedbakc_report) {
        [[RXFeedbackService sharedSDK] reportFeedbackLogWithData:data complete:^(NSDictionary * _Nullable response, RX_CommonRequestError * _Nullable error) {

        }];
    }
}

type 说明​

type备注
10001上报用户反馈日志
