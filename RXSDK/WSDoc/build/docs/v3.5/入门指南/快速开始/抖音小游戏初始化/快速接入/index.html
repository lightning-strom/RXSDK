快速接入

准备工作​

请登录望舒系统初始化相关服务，如果还没有望舒账号请查看准备工作说明。 望舒系统地址，可登录企业管理后台 > 已部署项目中查看。

环境要求​

  • 基础库最低版本：2.53.0，最高版本请选择稳定版本
  1. 点击下载 SDK 最新版本，下载抖音小游戏 SDK
  2. 把 SDK 导入项目工程中

SDK 初始化​

提示

初始化为异步调用，失败将不能使用 SDK 功能，请注意处理调用逻辑。

初始化 SDK 时需传入 productId、channelId、cpid、baseUrlList 参数信息。

参数参数类型是否必传描述
productIdstring是产品 id，望舒游戏发行平台创建产品，查看使用说明。
channelIdstring是渠道 id，望舒游戏发行平台创建渠道，查看使用说明。
cpidstring是CP id，望舒企业管理后台创建项目，查看使用说明。
baseUrlListstring[]是请求域名队列，望舒企业管理后台创建项目，查看使用说明。
completefunction是初始化回调函数

接口实例：

// 路径仅为示例，需要传入SDK在项目中的真实路径，如出现引用错误请检查路径是否正确
const channelSdk = require("your path/channelSDK/index.js")
//以下参数为测试参数，需要更换为接入方对应的参数
const sdk = new channelSdk({
    productId: '1', //产品 id  
    channelId: '818', //渠道id
    cpid: '1000049', //客户端id
    baseUrlList: ['https://ruixue.weiletest.com'],//请求域名队列
    complete: (data) => {
        console.log('init complete: ', data)
        if (data.code === 0) {
            // 初始化成功
        }
    },
})

设置自定义返回错误消息​

提示

规则 1：根据错误码直接读取对应提示替换 msg；

规则 2：如果表中有 default 的 key，将未配置的错误码 msg 统一替换为 default 的 value；

规则 3：$code$ $thirdcode$ $thirdmsg$ 为动态配置字段，如下所示，最终展示的信息为 支付错误4002

以上规则仅适用于调用了 setErrorMsg 接口，未调用保持原有规则

调用示例

// 同步函数
sdk.setErrorMsg({
   4001: 'cancel pay',
   4002: '支付错误$code$',
   2001: 'init fail',
   default: 'default$code$$thirdcode$'
})

sdk.getGameRecorderManager(
  {
    complete: (res) => {
        recorder = res.data
        // 录屏开始示例
        tt.getSystemInfo({
          success(res) {
            const screenWidth = res.screenWidth;
            const screenHeight = res.screenHeight;
            var maskInfo = recorder.getMark();
            var x = (screenWidth - maskInfo.markWidth) / 2;
            var y = (screenHeight - maskInfo.markHeight) / 2;
            recorder.onStart((res) => {
              console.log("录屏开始");
            });
            //添加水印并且居中处理
            recorder.start({
              duration: 30,
              isMarkOpen: true,
              locLeft: x,
              locTop: y,
            });
          },
        });
    },
  }
);

用户的排行榜能力​

设置写入用户的排行榜数据​

在关键的游戏场景，设置写入用户的排行榜数据（游戏成绩信息），该数据会上传到服务端。查看说明

参数说明​

| 字段 | 类型 | 是否必填 | 备注 | | ------------ | ------------------ | ---------------- | ---------------- | | params | IParams | 是 | 参数 | | callback | IMethodParams | 是 | 回调函数集合 |

IParams说明

| 字段 | 类型 | 是否必填 | 备注 | | ------------ | ------------ | ---------------- | ------------------------------------------------------------------------- | | value | string | 是 | 展示出来的数值，dataType 为 0 时只能传正数的字符串 （如'103', '105'）,且取值范围为 [0, int32_MAX)，否则会报错。dataType 为 1 时，则可传入任意字符串（eg：'青铜'、'白银'） | | dataType | number | 是 | 可选值: 0 或 1。0 表示数据为数字类型，往往适用于游戏的通关分数（如 103分、105分）； 1 表示数据为字符串类型，适用于段位信息（如 '青铜'、'白银'） | | zoneId | string | 否 | 排行榜分区标识，取值可以是 'default' 或 'test' 或其他开发者自定义的分区标识，'default' 表示为默认的线上分区，'test' 表示测试分区。不同分区的排行榜数据存在数据隔离，如 zoneId='test' 设置的数据不会影响通过 zoneId='default' 的排行榜，可用于测试环境。目前每个小游戏除了 default 和 test， 最多可支持 10 个分区 | | priority | number | 否 | 用于判断权重 ，仅当 dataType 为 1 时需要，不传则使用默认值 0。如传入 value 为'白银'，priority 为 2，则白银的权重为 2，传入value 为 '黄金'，priority 为 3，则黄金的权重为3，高于白银，届时生成的榜单，黄金段位会排在白银前面 | | extra | string | 否 | 预留字段 |

IMethodParams 说明

| 字段 | 备注 | | ------------ | ------------------------------------------------------------- | | complete | (data) => void complete：为函数且必传，data 为结果数据 |

调用示例

sdk.setImRankData(
  {
   dataType: 0, //成绩为数字类型
   value: "999999", //该用户得了999999分
   priority: 0, //dataType为数字类型，不需要权重，直接传0
   extra: "extra",
   zoneId: 'test'
  },
  {
    complete: (res) => {
        console.log(res)
    },
  }
);

| 字段 | 类型 | 是否必填 | 备注 | | ------------ | ------------------ | ---------------- | ---------------- | | params | IParams | 是 | 参数 | | callback | IMethodParams | 是 | 回调函数集合 |

IParams说明

sdk.requestFeedSubscribe({
		type: 'play',
		allScene: false,

		complete: (res) => {
			console.log(res)

				tt.showModal({
					title: "错误提示",
					content: res.msg
				})
			}
		}
})

function feedChangeCallback({ type }) {

        console.log('触发从Feed流进入小游戏事件回调')
    }
    if (type === 'feedExit') {
        console.log('触发从小游戏退回到Feed流事件回调')
    }
}

// 注册事件监听
