标识用户

选取合适的用户标识对于提高用户行为分析的准确性有非常大的影响，尤其是漏斗、留存、分布等用户相关的分析功能。因此，我们在进行任何数据接入之前，都应当先确定如何来标识用户。

下面会介绍望舒大数据平台(以下简称：大数据平台)用户标识的原理，以及几种典型情况下的用户标识方案。

摘要 一个用户会有两个 ID 进行识别，分别是：

  • 登录 ID（#distinct_id）：用户的登录 ID（rxopenid）。
    • 用户在登录状态下的标识，用来标识用户在登录后的数据，#distinct_id 字段上报时填写望舒 openid 字段数据。
  • 设备 ID（#devicecode）：用户在未登录状态下的 ID。
    • 用户在未登录状态下的标识，用来识别用户在登录前或者游戏外的数据，比如说注册前数据、广告数据等。

一、关联设备 ID 和登录 ID（一对一）​

适用场景​

成功关联设备 ID 和登录 ID 之后，用户在该设备 ID 上或该登录 ID 下的行为就会贯通，被认为是一个用户 ID 发生的。在进行事件、漏斗、留存等用户相关分析时也会算作一个用户。

案例​

详细步骤说明如下：

  1. 若某用户在华为手机上新安装了 App，并进行了一系列操作，生成的设备 ID (#devicecode)为 X，因为 默认的登录 ID (#distinct_id)不能为空，将设备 ID 的值赋给登录 ID，则登录 ID 也为 X，对应分配的用户 ID 为 1。
  2. 该用户进行了注册并登录，其登录 ID (#distinct_id)为 A，设备 ID X 和登录 ID A 关联成功，并将登录 ID A 存入 users 表的 #distinct_id 字段，用户 ID 仍为 1。
  3. 该用户登录之后继续进行一系列操作，发送的登录 ID 为 A，用户 ID 仍为 1。
  4. 该用户退出登录并进行了一系列操作，发送的登录 ID 为 A，仍使用用户 ID 1 来标识当前用户（因为登录 ID A 已与用户 ID 1 绑定）。
  5. 该用户把手机送给朋友了，朋友用自己的账号（已注册但未接入望舒系统）登录设备 X，登录 ID (#distinct_id)为 B，此时大数据平台将设备 ID X 与登录 ID B 进行关联，由于 X 已与 A 关联，所以此次关联失败，同时会分配一个新的用户 ID 2 来标识此用户，并将登录 ID B 同时存入 users 表的 #distinct_id 字段（用户的朋友账号上之前未关联过别的设备，且首次登录设备关联失败，则将登录 ID 同时记录到 #devicecode 上）。
  6. 之后，该用户的朋友一直使用账号 B 在设备 X 上进行了一系列操作，发送的 #distinct_id 为 B，大数据平台都使用用户 ID 2 来标识此用户（因为登录 ID B 已与用户 ID 2 绑定）。
  7. 该用户更换了一个新的苹果手机，并进行一系列操作，由于尚未登录，此时大数据平台使用全新的设备 ID Y 来标识此设备，发送的 #distinct_id 也为 Y，对应分配的用户 ID 为 3，则将用户 ID 3 、设备 ID Y 存入 users 表的 id, #distinct_id 和 #devicecode 字段。
  8. 该用户在苹果手机上使用账号 A 进行登录，虽然 A 已经与 X 关联，但是大数据平台以登录 ID A 为 优先唯一标识，此时大数据平台将设备 ID Y 与登录 ID A 进行关联，依然会切换到以 A 为登录 ID 的用户，其对应的用户 ID 依然为 1，此时账号 A 在 users 表中会关联到两台设备 ID （X 和 Y）。
  9. 该用户登录之后的后续操作，发送的 #distinct_id 为 A，所以仍以望舒 ID 1 标识。

在上述案例中，很大程度上已经实现了跨设备的用户贯通，但仍存在局限性：

  • 当用户换手机后，虽然登录账号之后的行为与换手机之前的行为贯通了，但是在新设备上首次登录之前的行为仍没法贯通，仍被识别为新的用户的行为。
  • 当用户把旧手机送给朋友之后，由于旧手机已被关联到自己的登录 ID 了，无法再与朋友的登录 ID 关联。后续使用这台旧手机的用户们，若不登录就操作，则都会被识别为同一个用户（旧手机成功关联的登录 ID ）。
