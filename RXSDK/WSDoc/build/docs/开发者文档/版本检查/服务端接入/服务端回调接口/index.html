自动打包​

目的：解决人工上传历史版本包太过耗时的自动化程序。

流程：策划创建并提交版本后， 开发人员在版本详情中点击自动打包， 望舒通知打包机， 打包机处理完成后再主动调用望舒将打包信息返回来。

四. CP方完成后回调望舒接口(api接口域名)​

POST： v1/developapi/autopacking/save

认证方式： Sign

请求参数​

参数类型备注
vidint版本 id
creator_idint操作人的 id
urlstring包地址, 如果压缩包根目录包含 ignore.txt 文件，会按照文件中每一行内容过滤压缩包中的内容，新生成的包不会包含这些文件和目录。

ignore.txt 内容示例

file1.js

file2.html

dir1

dir2/sub_dir2

dir3/sub_dir3/file3.html

文件内容说明

file1.js(过滤根目录 file1.js 子目录的不会过滤)

file2.html(过滤根目录 file2.html )

dir1(过滤根目录 dir1 和 dir1 下所有目录及文件)

dir2/sub_dir2(过滤目录 dir2/sub_dir2 下所有目录及文件)

dir3/sub_dir3/file3.html (过滤 dir3/sub_dir3/file3.html 单个文件) auto_packing_status

int2 开始打包 3 打包成功 4 打包失败 开始打包后打包机状态 10 构建中 20 排队中
mime 设置方式​

如果压缩包根目录包含mime.txt文件，会根据文件后缀设置 mime ，每行一种类型，使用英文“,”分割，前面是后缀，后面是 mime

mime.txt内容示例
txt,text/plain
jpeg,image/jpeg
json,application/json
md,text/markdown
yaml,text/yaml

文件内容说明
1、文件名：mime.txt
2、放在打包文件的根目录
3、上传后会删除 mime.txt文件
请求示例​

{{api 接口域名}}/v1/developapi/autopacking/save

{
 "vid": 1,
 "creator_id": 1,
 "url": "test/pkg/2212031ixs8R1HCKCJ0Ow8mA2GoXATXzMoHqr.zip",
 "auto_packing_status": 3
}
响应示例​
{
 "code": 0,
 "msg": ""
}

请求 header 中需带参数 Ruixue-Traceid 请求标识 Ruixue-Ts 时间戳 Ruixue-Sign 签名

签名使用 sha1 ， 示例：

// GetSign 生成签名方法
func GetSign(cpkey, traceID, ts string) string {
 h := sha1.New()
 _, _ = h.Write([]byte(traceID + ts + cpkey))
 ret := hex.EncodeToString(h.Sum(nil))
 h.Reset()
 return ret
}

💡 注意， cp 方需要将维度(product_id && channel_id)的数据全量替换为 data ， 望舒后台增删改产品包时，同步该产品包的部分信息示例：{"product_id": 1, "channel_id":818, "data": [{"channel_type": 1, "platform_id": 4, "appkey": "8da8d1c85c602355b8ca3a3de7c66049", ""loginip:"{"addr":"1"}"}]}data 数值长度为 0 时代表该产品包被删除
