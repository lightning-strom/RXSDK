接入 RDS 实名认证和防沉迷服务​

游戏实名认证与防沉迷​

按照国家新闻出版署《关于进一步严格管理切实防止未成年人沉迷网络游戏的通知》，各游戏出版运营企业均须在游戏内落实游戏实名认证和防沉迷新策略。

实名认证​

所有用户必须使用真实有效身份信息进行游戏账号注册并登录网络游戏。RDS 已为开发者自动对接了中宣部网络游戏防沉迷实名认证系统，并以开发者主体进行信息上报。

业务流程：

在玩家登录后，调用 SDK 实名认证的接口，如账号为未实名状态，则会触发实名认证界面，完成真实信息填写。

完成填写后，RDS 会将信息提交至中宣部系统中进行真实性校验（请先确认已完成开发者中心的配置工作，否则无法成功校验）。

防沉迷策略​

《通知》中要求，游戏企业必须严格管理未成年的游戏时间以及付费额度。SDK 封装了相应接口，游戏可通过 RDS 云端查询未成年玩家是否处于可以游戏的时间段内，以及未成年玩家的某笔消费是否受限。

游戏时间限制：渠道开启防沉迷后，18 岁以下用户无法登录。仅允许未成年人在周五、周六、周日和法定节假日的 20:00 至 21:00 进行游戏。

充值额度限制：

  • 不满 8 岁，无法在游戏内进行充值
  • 满 8 岁，不满 16 岁：单次充值 ≤ 50 元，单月充值累计 ≤ 200 元
  • 满 16 岁，不满 18 岁：单次充值 ≤ 100 元，单月充值累计 ≤ 400 元

鸿蒙端使用 TypeScript API 调用：

/**
 * 显示实名认证界面
 * 引导用户完成实名认证流程，支持自定义奖励和回调通知
 * @param uiContext - UI上下文对象
 * @param callback - 可选回调函数，用于接收实名认证结果
 * 回调参数格式：{ code: number, message: string, data?: RealNameResult }
 * - code: 状态码（0表示成功，非0表示失败）
 * - message: 操作消息（如"认证成功"、"用户取消"）
 * - data: 认证结果数据，包含用户实名信息
 * @returns 返回对话框控制器实例
 */
showRealNameUI(uiContext: UIContext, callback?: RCallback<RealNameResult>): IBaseDialog<RealNameResult>

调用示例：

RXApi.getInstance().showRealNameUI(this.uiContext, (result) => {
  if (result.code === 0) {
    console.log("实名认证成功:", result.data);
    refreshUserInfo();
  } else {
    console.error("实名认证失败:", result.message);
  }
});

常见问题​

个人 / 团体的开发者需要接入防沉迷吗？​

按照国家新闻出版署《关于进一步严格管理切实防止未成年人沉迷网络游戏的通知》，各游戏出版运营企业均须在游戏内落实游戏实名认证和防沉迷新策略。

防沉迷和登录是什么关系？​

防沉迷弹窗需要项目组自定义弹出时机。集成望舒登录后（必须启用实名认证），望舒会返回用户年龄、用户剩余游戏时长（根据实名信息计算）。一般项目会根据以上信息自行计算何时弹出防沉迷弹窗。

用户充值时，需要项目组传参是否启用防沉迷校验。如果启用防沉迷校验，调用支付接口后，望舒会返回具体的错误码。

如何配置实名认证与防沉迷服务？​

登录望舒系统，菜单位置：基础配置 > 法务相关 > 防沉迷配置。
