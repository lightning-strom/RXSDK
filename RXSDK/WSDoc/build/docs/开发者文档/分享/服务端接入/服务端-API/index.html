服务端 API

获取通路配置​

**GET: ** /v1/operationapi/share/platforms

认证方式： 无

CURL 示例​

curl --location --request GET '{{接口域名}}/v1/operationapi/share/platforms'

响应示例

{
 "data": { // 值为-1时表示不限制,值使用 | 运算 为将来扩展做准备
 "wechat": { // 微信配置
 "lure": -1, // 诱导类
 "achievement": 1, // 成就类
 "special": 2 // 特殊类
 }
 },
 "code": 0
}

响应结构（JSON）​

字段类型说明
codeNumber状态码 0 为成功
msgString失败时的错误信息
dataMap[String]Data返回信息, key 为平台名， 例如 wechat 值参考 API

通路配置Data​

字段类型说明
lureNumber诱导类 值参考 API
achievementNumber成就类 值参考 API
specialNumber返回信息 值参考 API

获取分享数据​

**POST: ** /v1/operationapi/share/data

认证方式： 无

CURL 示例​

curl --location --request POST '{{接口域名}}/v1/operationapi/share/data' \
--header 'Content-Type: application/json' \
--data-raw '{
 "product_id": "26",
 "channel_id": "20",
 "func": "eiusmod commodo occaecat in in",
 "platform": "aliqua",
 "type": "dolore elit est",
 "open_id": "84",
 "sub_channel_id": "22",
 "region": "aliqua Lorem eiusmod culpa in",
 "transmits": "elit quis laboris dolore proident"
}'

请求示例

{
 "product_id" : "1",
 "channel_id" : "1",
 "open_id": "84",
 "sub_channel_id": "2",
 "region" : "210201",
 "func" : "youdao",
 "platform" : "wechat",
 "type" : "app",
 "transmits" : "a=2&b=3"
}

请求参数（JSON）​

参数类型是否必填备注
product_idString是产品 ID
channel_idString是渠道 ID
sub_channel_idString否子渠道 ID ，通行证下发,没有传空字符串或者不传
regionString否地区码，没有则不传，会取全国地区的数据。 望舒地区码列表
funcString是埋点标记
platformString是平台 微信（ wechat ）、脸书（ facebook ）、QQ(qq) 抖音(douyin) 参考望舒后台通路
typeString是客户端类型 app （应用 App ） mini(小游戏)
transmitsString否透传参数，原样返回， 请使用 key=value 形式，并对值使用 urlencode ，返回时会原样返回， 当 key 为 use_url_param=true 时， 将不使用短链接返回，而是将所有参数拼接到 url 中
open_idString是用户的 OpenID

分享调度​

当埋点配置了分享调度后，诱导类分享会根据分享调度策略决定用户是分享还是广告， 分享成功或者失败， 返回值中会增加 scheduling 对象，值如下：

获取分享调度Scheduling​

字段类型说明
scheduling_typeString值为 ad 时为广告， share 时为分享。
scheduling_signString调度策略当前可分享看广告总数密文, 需用 aes 解密，使用 cpkey 作为 key。
解出值转为字符串， 格式: "type=share&count=10&uuid=xxx&ts=1695796034&ddid=a" 详情scheduling_eventNumber
1 分享成功 -1 分享失败scheduling_failed_msgString
分享失败时的信息
scheduling_sign对应标识​
字段类型说明
typeString值为 ad 时为广告， share 时为分享。
countNumber调度策略当前可分享看广告总数
uuidString唯一标识
tsNumber时间戳
ddidString调度标识

响应策略为分享时​

{
 "data": {
 "trigger": {// 埋点数据
 ...
 },
 "strategy": { // 策略数据
 ...
 },
 "content": { // 分享素材数据
 ...
 },
 "platforms": { // 平台信息,代表某个平台可用的分享方式 -1代表不限制 用于CP方不接sdk的情况.sdk方式通过分享通路配置获取此项配置.
 "wechat": -1 // 微信, 1:好友 2:朋友圈 -1:不限制
 },
 "platform": "wechat", // 当前分享的平台,即客户端传啥 给返回啥
 "example_platforms": { // 正式时不返回,此项用于验证平台信息是否正确
 ...
 },
 "identity": "wx", // 平台标识,如果是微信时返回的为微信ID
 "transmits": "a=2&b=3",
 "scheduling": {
 "scheduling_type": "share",
 "scheduling_sign": "xx",
 "scheduling_event": -1,
 "scheduling_failed_msg": "诱导类失败", // 错误提示
 }
 },
 "code": 0
}

只返回埋点和透传信息

分享调度失败原因参考下表​

错误码错误描述解决方法
305405操作频繁，请稍后再试该用户触发了 基础配置=>分享管理=>埋点配置的触发时间间隔
305406今日分享次数已达上限该用户触发了 商业化基础配置=>分享广告配置=>分享广告次数配置=>次数限制
305407今日循环调度次数已达上限该用触发了 商业化基础配置=>分享广告配置=>分享广告调度策略=>循环次数限制
305408分享调度策略未命中商业化基础配置=>分享广告配置=>分享广告调度策略中的调度策略没有覆盖用户的条件
305409app 有效用户界定不存在缺少配置信息： 商业化基础配置=>分享广告配置=>分享广告次数配置=>游戏&无效用界定=>APP
305410小游戏有效用户界定不存在缺少配置信息： 商业化基础配置=>分享广告配置=>分享广告次数配置=>游戏&无效用界定=>小游戏
305411分享失败提示语不存在缺少配置信息： 商业化基础配置=>分享广告配置=>分享广告次数配置=>分享失败概率&提示
305412分享次数限制不存在缺少配置信息： 商业化基础配置=>分享广告配置=>分享广告次数配置=>次数限制
305413分享调度策略不存在商业化基础配置=>分享广告配置=>分享广告调度策略中没有用户的埋点或用户类型未配置
305414分享调度策略虽然命中但配置无效商业化基础配置=>分享广告配置=>分享广告调度策略中未配置循环策略

调度初始化​

**POST: ** /v1/operationapi/scheduling/init

认证方式： 无

需要获取用户表示，必须在登录后再调用该接口。适用场景：在获取调度内容之前，先批量获取埋点的调度策略所命中的是分享还是广告

CURL 示例​

curl --location --request POST '{{接口域名}}/v1/operationapi/scheduling/init' \
--header 'Content-Type: application/json' \
--data-raw '{
 "func": ["share"],
 "type": "app",
 "open_id": "123"
}'

请求示例

{
 "func" : ["share"],
 "type" : "app",
 "open_id": "123"
}

请求参数（JSON）​

参数类型是否必填备注
funcArray否需要获取的埋点标识，不传返回全部
typeString是类型 app、mini
open_idString是望舒 openid

响应示例：

{
 "code": 0,
 "msg":"",
 "data": "func1": {
 "scheduling_sign": "xx",
 "scheduling_type": "ad",
 "user_type": 1, // 1有效用户 2无效用户
 }
}

响应参数（JSON）​

未命中策略的埋点不返回

参数类型是否必填备注
scheduling_signString是调度分享看广告总次数
scheduling_typeString是分享 share 广告 ad
user_typeNumber是用户状态 1 有效用户 2 无效用户

短连接解析​

**GET: ** /v1/operationapi/url/parse

认证方式： 无

CURL 示例​

curl --location --request GET '{{接口域名}}/v1/operationapi/url/parse?identity=xxx'

请求参数​

参数类型是否必填备注
identityString是短连接标识

注意，短连接默认有效时间为 7 天，当 6 天后有用户调用本接口解析短连接时，短连接有效期会重新计算

短链接标识在哪取？

取自根据客户端传入参数获取分享数据 返回数据中的 content.url 字段，具体如下图。

获取自动重定向短链接​

**POST: ** /v1/url/short

认证方式： [AccessToken]

CURL 示例​

curl --location --request POST '{{接口域名}}/v1/url/short' \
--header 'Content-Type: application/json' \
--data-raw '{
 "url": "http://baidu.com"
}'

请求参数​

参数类型是否必填备注
urlString是要跳转的链接地址
titleString否填充海外 meta 值 og:title
contentString否填充海外 meta 值 og:description
imageString否填充海外 meta 值 og:image
extString否预留字段

响应示例：

{
 "code": 0,
 "msg":"",
 "data": {"short_url": "{{分享短链接域名}}/v1/url/redirect?d=xxxxx"}
}

响应结构（JSON）​

字段类型说明
codeNumber状态码 0 为成功
msgString失败时的错误信息
dataMap短链接地址， 当请求短链接时自动重定向到原地址
