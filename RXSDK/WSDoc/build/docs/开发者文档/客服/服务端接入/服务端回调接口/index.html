服务端回调接口

通过望舒 openid 换取游戏用户 id​

类型：同步

Action: user-get_id

认证方式： CPSign

请求参数​

字段类型是否必填说明
open_id[]String是望舒 openid 数组

请求示例​

[
 "open_id_1",
 "open_id_2"
]

返回示例​

[
 "user_id_1",
 "user_id_2"
]

响应要求​

字段类型说明
codeNumber0 成功
msgString错误信息
data[]String游戏用户 id 数组

抖音客服消息转发​

类型：同步 根据事件类型决定

Action: channel-notify

认证方式： CPSign

请求参数​

字段类型是否必填说明
methodString是默认： minigame_douyin
channel_notify_typestring是默认： gift_delivery
cp_user_idString是游戏 ID
rx_openid_idString是望舒 openid
rawObject是抖音的原始数据 JSON 格式

Object（消息类型：gift_delivery）​

字段名字段类型必须说明
gift_idint64否发货时对应的礼包 ID ，正式请求一般有，在道具测试阶段无
play_typeint8否发货时对应的礼包类型枚举，与 gift_id 共同存在

枚举： 3(游戏登录礼包), 4(游戏站签到礼包), 5(平台托管礼包) channel

int8否对应托管礼包发送时的渠道枚举： 3(用户权益中心)
gift_namestring否
发货时对应的礼包名称，与 gift_id 共同存在gift_codestring
是此次发货使用的礼包码，可用于消息去重

注意

在执行发货时，无法避免同一条发货消息的重复推送，开发者需通过 gift_code 保障幂等（保留 24 小时即可），避免同一个 gift_code 被多次使用，造成损失

字段类型是否必填说明
open_idstring是领奖用户的 open_id
prop_listarray是此次发货的道具列表，正常情况下，开发者需给用户账号增加这些道具资产
prop_list.prop_idstring是道具列表中当前道具的道具 ID
prop_list.namestring是道具列表中当前道具的道具名称
prop_list.countint64是道具列表中当前道具的发货数量
env.typestring是发货请求的环境标识

  • development ：调试环境，使用平台测试推送入口时使用

  • production ：正式环境，用户正式领取礼包时使用 send_time | int64 | 是 | 礼包推送请求触发的秒级时间戳 | | --- | --- | --- |
