任务管理

一、功能介绍​

二、操作步骤​

1.点击左侧 任务管理>任务管理 进入该功能页面。 2.创建任务​

画布上怎么工作​

  • 从左侧把节点拖到画布，用连线把节点串起来，表示对话按顺序或按分支往下走。
  • 开始节点是每个任务的入口，通常整个流程从这里接到第一个业务节点。
  • 双击节点或连线（以实际界面操作为准）可打开配置窗口；保存任务前系统会检查必填项是否完整。

关于「分支」：三种特殊的线​

有些节点本身不负责写复杂规则，真正的判断写在「从该节点拉出去的连线」上：

从哪种节点拉线这条线在做什么
条件节点按变量是否满足条件，决定走哪条分支（可设多组条件）。
选项节点按用户说的话是否匹配某条分支上的说法，决定下一步去哪。
计数节点按对话中某计数是否满足（例如第几次），决定走哪条分支。

从上述三类节点拖出新连线时，系统会自动把这条线当成对应的「条件线 / 选项线 / 计数线」，请在线的配置里填好规则。

普通节点之间用连线连接时，一般是普通连线，表示执行完上一步就进入下一步。

各节点说明​

开始节点​

  • 作用：标记流程起点，连接后续节点即可。
  • 配置：一般无需单独填写业务表单。

收集节点​

  • 作用：通过多轮问答，向用户收集信息（例如手机号、意向、标签等），并写入会话数据，供后面节点使用。
  • 典型配置：引导用户怎么回答、收集哪一项、是否必填、最多追问几轮、超时或答不上来时怎么提示等；可与实体、槽位等能力配合（以界面选项为准）。
  • 使用提示：若后面要在回复或大模型里引用收集到的内容，需先在本节点完成收集。

回复节点​

  • 作用：机器人发送一段固定话术（可附带推荐问题等）。
  • 典型配置：回复正文；可选关联知识/问题。
  • 使用提示：若话术里需要插入会话中已有的变量，请按系统支持的占位格式填写（保存时若格式不对会提示检查）。

条件节点​

  • 作用：做条件分支。节点本身几乎不填内容，分支条件在从本节点连出去的各条「条件线」上配置（例如某变量等于某值、大于某数等）。
  • 使用提示：可为不同条件接不同后续节点；多组条件的关系以系统内配置方式为准（例如一组内多条需同时满足等）。

选项节点​

  • 作用：先让机器人说一段话，并（可选）展示选项；用户开口后，根据匹配哪一条分支上的用户说法，走到不同后续节点。
  • 节点上：机器人话术、选项文案、是否展示选项等。
  • 连线上：每条分支需配置匹配方式（如完全一致、正则、语义相近等）以及用户可能怎么说的语料。
  • 使用提示：有几个去向就要有几条带选项规则的分支线，并分别接到对应节点。

人工节点​

  • 作用：在适当时机转人工，向用户展示转接说明或排队提示等。
  • 典型配置：转人工前机器人要说的引导语。

流程节点​

  • 作用：把用户转入另一个已配置好的任务继续对话（子流程/任务跳转）。
  • 典型配置：选择要跳转的目标任务。
  • 使用提示：用于复用已有流程或拆分大流程，注意目标任务需已存在且配置完整。

随机节点​

  • 作用：从预先准备的多条回复中随机选一条发给用户，让话术不那么死板；可关联知识问题。
  • 典型配置：多条候选回复文案；可选关联知识。

计数节点​

  • 作用：按次数类条件分支（例如第 1 次、第 3 次以后走不同分支）。节点本身几乎不填规则，规则在从本节点拉出的「计数线」上配置。
  • 连线上：设置比较关系（如等于、大于等）与次数阈值。

LLM 节点（大模型）​

  • 作用：调用大模型，根据你写的系统提示 / 用户提示生成内容，并把结果存到会话里，供后续节点引用。
  • 典型配置：使用哪个模型、温度等参数；提示词里可引用当前会话里已有的信息；需指定一个结果保存名称（便于后面用「变量/路径」方式引用）。
  • 使用提示：若需要模型按固定 JSON 结构输出，需在界面中选择结构化输出方式并填写相应说明（以界面为准）。

代码执行节点​

  • 作用：在受控环境中执行一段 Python 代码，对会话里已有数据做计算或转换，再把结果写回会话。
  • 典型配置：代码正文；声明从会话里取哪些字段作为输入；指定结果保存名称；若输出要是 JSON 结构，按界面要求填写结构说明。
  • 使用提示：适合有简单脚本能力的配置人员；代码与输入输出需与界面说明一致，否则保存或运行会失败。

API 节点​

  • 作用：发起一次 HTTP 请求（如查询业务接口），把返回内容写入会话，供后续节点使用。
  • 典型配置：地址、方法、请求头、请求体；指定结果保存名称；通常还需填一个返回数据示例（用于说明接口长什么样，便于检查配置是否合理）。
  • 使用提示：地址、请求头、请求体中往往可以写占位符，引用会话里已有字段（具体写法以系统说明为准）；若系统提供「调试」能力，可先调试再上线。

保存失败时可以先检查什么​

不同节点要求不同，常见情况包括：

  • 节点名称、必填项未填完整。
  • 收集节点：至少配置一条有效的收集项。
  • 回复节点：回复正文不能为空；若用了变量占位，格式需合法。
  • 选项 / 条件 / 计数相关的连线：对应线上的规则、语料、次数等未配全。
  • 流程节点：未选择目标任务。
  • 大模型 / 代码 / API：未填写模型与提示、或代码、或地址等关键项；API 的请求头、返回示例等需为合法 JSON 格式（按界面提示）。

按界面红色提示或报错文案逐项补全即可。

节点在画布上的颜色（便于辨认）​

各节点有固定配色，方便一眼区分类型（开始、收集、回复、条件、选项、人工、流程、随机、计数、大模型、代码、API 等）。若副标题区域有简短说明，多为该节点关键信息的摘要（如回复摘要、模型名、接口方法等）。
