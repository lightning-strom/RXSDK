项目理解

在获得瑞雪系统账号，确认可以登录大数据平台之后，您就需要对您的项目进行理解和分析，了解您需要监控的指标和需要分析的事件，从而决定要传输什么样的数据；在开始之前，我们会先为您介绍 Event & User 模型，这对您理解与使用瑞雪大数据平台至关重要。

一、Event & User 模型的介绍​

  1. Event 表示用户某个或一系列有意义的行为。例如用户登录游戏账号、购买了一个游戏道具等。 一条 Event 主要包含两部分信息： a. 描述行为是如何发生的。例如行为的名称、产生行为的用户、行为发生的时间等。 b. 描述行为发生了什么。例如用户购买游戏道具时支付的金额、分享的具体内容等。 这些信息，我们称之为事件属性。
  2. User 被用于描述单个用户的最新状态和固定行为。例如用户 ID、首次注册时间、累计付费金额等。
用户 ID 用来标识一名用户，非常重要。在大数据平台中，我们用瑞雪 OpenID 作为用户 ID，如果您希望了解瑞雪如何识别用户，可以查看用户[识别规则](https://doc.ruixueyun.com/#/view?path=4c7b2be1-bb3e-4fbb-9279-24248d46c3ef)。

根据 User 的属性，可以在用户行为分析时筛选出需要的用户。例如需要分析注册时间在 2022-10-10 后的用户登录情况，则只要「首次注册时间」> 2022-10-10 即可。

二、整理需求​

在完成前期准备之后，您可以开始着手整理分析需求，如果您对于该流程不太熟悉的话，可以遵循下列步骤来完成需求整理：

2.1 明确基础的分析指标​

瑞雪大数据平台提供了预置事件和预置属性，预置事件包括注册、登录、付费、分享等，详细参考预置事件和预置属性 。除了预置事件外，游戏方需要整理支持项目数据分析场景的自定义事件、事件属性和用户属性（注：请使用大数据平台提供的 自定义 Event 和用户属性 Excel 表格模板对所有自定义 Event 进行整理）。

2.2 确定追踪的事件​

在确定基础指标之后，建议您将应用中的，考量每个系统、功能的重要程度以及分析点，再将需要分析的玩法及其分析点转化为 Event 的形式。

必须通过大数据平台提供的自定义 Event 和用户属性 Excel 表格模板对所有 Event 进行整理，模板当中需要包含所有 Event 的名称、属性名称、描述等，文档整理完成后需要上传到大数据平台埋点方案中，埋点方案作为数据上报的唯一标准数据结构，同时这份文档也能够帮助您在设置属性以及埋点时与技术人员进行沟通。
Excel 模板可以在 **数据管理 > 埋点管理 > 埋点方案 > 埋点事件** 及用户属性批量上传页面下载。

如果您对于如何将分析需求转化为 Event 的形式存有疑惑，可以参考我们给出的下列建议：

  • 重要的行为，推荐一个行为设定为一个 Event，再根据您的分析点进行属性的设置。
  • 不重要的行为，比如只需要分析参与次数、参与人数的行为，您可以将多个这样的行为设置成一个 Event，再通过属性的方式标识具体的行为，比如设置一个 Event 叫 次要事件，再通过一个属性 事件类型 来说明追踪的是那个行为。
  • 如果特别关注某些关键行为，比如付费购买行为中的一键购买，可以单独将这一行为作为一个 Event 进行追踪。

将之前整理的事件 Excel 文档成功上传到埋点方案中后，您需要选择您的接入方式，您可以使用客户端和服务端进行数据上报，详细内容可参考数据上报，瑞雪 SDK 可参考 iOS SDK 、 Android SDK、JavaScript SDK、Go SDK、服务端 API

2.3 确定用户标识规则​

瑞雪大数据平台标识一个用户用 登录 ID（#distinct_id），也就是瑞雪 OpenID。对于不同的数据来源，比如 iOS 端和 Android 端，如果您通过客户端 SDK 和服务端 SDK 接入的方式上传数据，也是用登录 ID 识别用户。
