## 查询用户分数

* ( ) JS::scorejs5
* ( ) Unity::scorejs6

| **字段** | **类型**                         | **是否必填** | **说明** | **示例** |

## 开放数据

### 获取当前用户互动型托管数据对应 key 的数据

* ( ) JS::scorejs11
* ( ) Unity::scorejs12

#### 响应结构

请参考 [微信开放数据解密 API](/docs/v3.5/排行榜/服务端接入/服务端 API) 响应结构。

### 对用户托管数据进行写数据操作

**托管数据的限制**
1. 每个 openid 所标识的微信用户在每个游戏上托管的数据不能超过 128 个 key-value 对。
2. 上报的 key-value 列表当中每一项的 key+value 长度都不能超过 1K(1024) 字节。
3. 上报的 key-value 列表当中每一个 key 长度都不能超过 128 字节。

* ( ) JS::scorejs13
* ( ) Unity::scorejs14

#### 响应结构

成功 code 为 0

### 获取当前用户托管数据当中对应 key 的数据

该接口只可在开放数据域下使用
[开放数据域使用指南](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/opendata/basic.html)

* ( ) JS::scorejs15
* ( ) Unity::scorejs16

#### 响应结构

| **字段**
 | **类型**
 | **备注**
                                                                                                                                  |
| ------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| code
     | number
   | 0: 表示成功
                                                                                                                               |
| msg
      | string
   | 仅在 code 为非 0 时不为空
                                                                                                                 |
| data
     | KVData[]
 | 用户的托管 KV 数据列表，
结构参考 [微信小游戏 KVData](https://developers.weixin.qq.com/minigame/dev/api/open-api/data/KVData.html) 
 |

**响应示例**

```json
{
    "code":0,
    "data":[
        {
            "key":"score",
            "value":"{\"wxgame\":{\"score\":16,\"update_time\": 1513080573},\"cost_ms\":36500}"
        }
    ]
}
```
