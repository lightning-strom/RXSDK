补单机制：
由于app在上传凭证给服务器时发生了网络或各种原因，造成了凭证没有上传成功，产生了掉单，SDK 提供自动和客户端手动补单两种补偿机制。具体如下：

自动补单流程：

1. 客户端调用下单接口时 SDK 会优先判断上次支付是否掉单，如有掉单则先进行补单，补单成功后再次调用下单接口则恢复正常支付流程。补单失败后再次调用下单接口则继续补单。
2. 支付失败后和登录成功后SDK会自动进行5次补单，使用斐波那契数列5秒间隔计算，减少掉单率。

手动补单流程：

1. 订单验证失败 SDK 会将订单号及支付凭证回调给客户端，客户端可自行上报。
2. SDK 提供查询是否需要补单和补单功能，客户端可配合使用。建议在支付失败后和登录成功后调用。
   :::

## 补单

**米大师虚拟支付流程：**

通过望舒后台构建商品后调用 SDK **下单**接口，服务端验证通过后 SDK 拉起**米大师虚拟支付**进行支付，米大师虚拟支付成功后，SDK 回调**望舒服务端，**由**望舒服务端**通知**客户端服务端**进行发货。

**米大师虚拟支付补单机制：**

由于 SDK 在回调**望舒服务器**时发生了网络或各种原因，造成回调没有成功，产生了掉单，SDK 提供自动和客户端手动补单两种补偿机制。**具体如下：**

**自动补单流程**：

1. 客户端调用下单接口时 SDK 会优先判断上次支付是否掉单，如有掉单则先进行补单，**补单成功**后并移除本地缓存的补单信息，再次调用下单接口则恢复正常支付流程。**补单失败**后再次调用下单接口则继续补单。

**手动补单流程：**

1. 订单验证失败 SDK 会将订单号等补单信息回调给客户端，客户端可自行上报。
2. SDK 提供**查询是否需要补单**和**补单**功能，客户端可配合使用。建议在**支付失败**后和**登录成功**后调用。
