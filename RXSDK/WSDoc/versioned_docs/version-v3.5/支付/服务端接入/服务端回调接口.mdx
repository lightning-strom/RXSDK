## 苹果支付用户申请退款通知 CP 接口

用户使用苹果支付，申请退款时苹果服务器会通知望舒,望舒将消息处理后转发给 CP 服务器

> 类型：异步
> Action: ke-appstore-refund-request
> **认证方式：** [CPSign](/docs/v3.5/入门指南/服务端接入须知)

:::tip
需要在苹果官方后台配置回调地址通知望舒规则:api 域名 +/v1/ke/refund/产品 ID/appstore
例如:api 域名是 [http://api.weiletest.com](http://api.weiletest.com) 产品 ID 是 6324

那么 完整的域名则是 [http://api.weiletest.com/v1/ke/refund/6324/appstore](http://api.weiletest.com/v1/ke/refund/6324/appstore)

:::

### 请求参数

| <strong>字段</strong> | <strong>类型</strong> | <strong>是否必填</strong> | <strong>说明</strong> |
| --- | --- | ---- | --- |
| order\_no | String | 否 | 望舒订单号 |
| trade\_no | String | 否 | CP 订单号 |
| platform\_no | String | 否 | 三方平台订单号 |
| transmit\_args | String | 否 | 客户端透传参数 |
| goods\_tag | String | 否 | 望舒后台配置计费点标识 |
| goods\_name | String | 否 | 商品名称 |
| price | Number | 否 | 支付金额 单位 分 |
| currency | String | 否 | 支付币种 |
| openid | String | 否 | 望舒 openid |
| translation\_id | String | 是 | 苹果退款 translation\_id 当只有 translation\_id 没有 order\_no 等其他参数时代表这笔订单无法在望舒中查询到,属于接入望舒系统之前的订单,或者用户掉单,这种情况需要 CP 自行判断和处理 |

#### 请求示例

```json
{
        "order_no": "22083142794459",
        "trade_no": "1050962#1661917993640",
        "platform_no": "2022083122001428061443103894",
        "transmit_args": "{\"userid\":1050962}",
        "goods_tag": "weile_cat_chongzhi6",
        "goods_name": "6元钻石直充",
        "price": 600,
        "currency": "CNY",
        "openid": "rxuCMrWjdxEZB0HBPzqSBlbzX3_zK8A1",
        "translation_id":"123123123891239"
}
```

#### 返回示例

```json
{
"code": 0  
}
```

### 响应要求

| <strong>字段</strong> | <strong>类型</strong> | <strong>说明</strong> |
| --- | --- | --- |
| code | Number | 0 成功 |
| msg | String | 错误信息 |
| data | Any | 需要返回数据时放到此字段 |

## 苹果谷歌支付用户退款成功通知 CP 接口

> 类型：异步
> Action: ke-appstore-refund-success
> **认证方式：** [CPSign](/docs/v3.5/入门指南/服务端接入须知)

:::tip
apple支付: 需要在苹果官方后台配置回调地址通知望舒规则:api 域名 +/v1/ke/refund/产品 ID/渠道ID/appstore

1. 需要在google配置pubsub[https://developer.android.google.cn/google/play/billing/getting-ready?hl=th#setup-pubsub](https://developer.android.google.cn/google/play/billing/getting-ready?hl=th#setup-pubsub)
    规则:api 域名 +/v1/ke/refund/产品 ID/渠道ID/google
    例如:api 域名是 [http://api.weiletest.com](http://api.weiletest.com) 产品 ID 是 6324 渠道是100
    那么 google sub 推送配置完整的域名则是 [http://api.weiletest.com/v1/ke/refund/6324/100/google](http://api.weiletest.com/v1/ke/refund/6324/100/google)
2. 需要在望舒配置有对应权限的serveraccount账号

:::

## 支付成功通知 CP 接口

用户完成支付后，望舒服务会根据 CP 下单时候传递的 notify\_url 通知 CP 服务器支付成功（若没传 notify\_url，则取望舒后台配置的 CP 支付成功地址。[CP 支付成功地址回调配置位置](/docs/v3.5/支付/服务端接入/服务端回调接口)），CP 需要在接收到该通知后对通知信息进行校验和对成功订单进行处理，CP 需要自行处理重复通知逻辑，确保一笔订单重复通知到 CP，CP 也只发一次货
:::tip
望舒在通知CP发货时，CP侧如果返回了失败。望舒会触发重试机制：第一次5s  第二次 10s 第三次 30s  然后都是隔60s每次，  总共12次。
:::
> 类型：同步
> Action: ke-notify
> **认证方式：** [CPSign](/docs/v3.5/入门指南/服务端接入须知)

### 

<strong>请求参数</strong>

| <strong>字段</strong> | <strong>类型</strong> | <strong>是否必填</strong> | <strong>说明</strong> |
| --- | --- | ---- | --- |
| order\_no | String | 是 | 望舒订单号 |
| trade\_no | String | 是 | CP 订单号 |
| platform\_no | String | 否 | 三方平台订单号 |
| transmit\_args | String | 是 | 客户端透传参数 |
| goods\_tag | String | 是 | 望舒后台配置计费点标识 |
| goods\_name | String | 是 | 商品名称 |
| price | Number | 是 | 支付金额 单位 分 |
| currency | String | 是 | 支付币种 |
| openid | String | 是 | 望舒 openid |
| cp_user_id | String | 否 | 用户id |
| sub\_pay | String | 否 | 非必定返回字段 子支付方式 例如:银联渠道-> 子支付方式使用支付宝 |
| card\_price | Number | 否 | 非必定返回字段 充值卡金额-> 海外 UPAY 支付使用充值卡支付返回该字段 |
| call\_from | String | 否 | 非必定返回字段 目前使用场景为区分微信小游戏回调方式，值为 wx\_mini\_subscribe 为微信小游戏订阅回调 |
| force\_repair | Boolean | 否 | 是否强制补单 |

#### 请求示例

```json
{
        "order_no": "22083142794459",
        "trade_no": "1050962#1661917993640",
        "platform_no": "2022083122001428061443103894",
        "transmit_args": "{\"userid\":1050962}",
        "goods_tag": "weile_cat_chongzhi6",
        "goods_name": "6元钻石直充",
        "price": 600,
        "currency": "CNY",
        "openid": "rxuCMrWjdxEZB0HBPzqSBlbzX3_zK8A1",
        "force_repair":false
}
```

#### 返回示例

```json
{
    "code": 0  // 返回非0都代表CP处理失败 失败订单望舒服务器会在一个小时内每隔5分钟尝试重复通知CP，直到CP返回
}
```

### 响应要求

| <strong>字段</strong> | <strong>类型</strong> | <strong>说明</strong> |
| --- | --- | --- |
| code | Number | 0 成功 |
| msg | String | 错误信息 |
| data | Any | 需要返回数据时放到此字段 |

## 通知CP下单接口

在特殊的运营场景下会在望舒侧直接下单

> 类型：同步
> Action: ke-cporder
> **认证方式：** [CPSign](/docs/v3.5/入门指南/服务端接入须知)

### 

<strong>请求参数</strong>

| <strong>字段</strong> | <strong>类型</strong> | <strong>是否必填</strong> | <strong>说明</strong> |
| --- | --- | ---- | --- |
| goods_tag | String | 是 |计费点 |
| openid | String | 是 |望舒openid |
| cp_user_id | String | 否 |cp用户id |
|pay_type|String|是|支付方式|
|amount|Number|是|支付金额 单位分|
|currency|String|否|币种 国内默认CNY|
|country|String|否|国家|
|env|Number|否|否测试环境 1 测试环境|
|scene|String|否|下单场景|

#### 请求示例

```json
{
        "goods_tag":"394991",
        "cp_user_id":"4281941",
        "openid": "rxuCMrWjdxEZB0HBPzqSBlbzX3_zK8A1",
        "pay_type":"alipay",
        "amount":1,
        "currency":"CNY"
        "country":"CN",
        "env":0,
        "scene":"rx_shop"
        
}
```

#### 返回示例

```json
{
    "code": 0  //
    "data":{
        "trade_no":"11111",
        "notify_url":"",
        "ext":{
            "a":1,
            "b":"2"
        }
    } 
}
```

### 响应要求

| <strong>字段</strong> | <strong>类型</strong> | <strong>说明</strong> |
| --- | --- | --- |
| code | Number | 0 成功 |
| msg | String | 错误信息 |
| data | Object | 需要返回数据时放到此字段 |
| data.trade_no | String | CP侧订单号 |
| data.notify_url| String |通知CP回调地址,如果为空则使用望舒后台配置|
| data.ext | Any | 附加扩展字段 例如checout风控参数 |

## 道具兑换接口

用于特定场景下用户使用道具兑换道具的情况

> 类型：同步
> Action: item_redemption
> **认证方式：** [CPSign](/docs/v3.5/入门指南/服务端接入须知)

### 

<strong>请求参数</strong>

| <strong>字段</strong> | <strong>类型</strong> | <strong>是否必填</strong> | <strong>说明</strong> |
| --- | --- | ---- | --- |
| openid | String | 是 |望舒openid |
| cp_user_id | String | 否 |cp用户id |
| user_id | String | 否 |cp用户id |
|consumptions|[]AttrItem|是|用户消耗道具列表|
|increases|[]AttrItem|是|用户获得道具列表|
 <strong>AttrItem</strong>

| <strong>字段</strong> | <strong>类型</strong> | <strong>是否必填</strong> | <strong>说明</strong> |
| --- | --- | ---- | --- |
| prop | String | 是 |道具标识  |
| num|Number| 是 | 道具数量 |

#### 请求示例

```json
{
      
        "cp_user_id":"4281941",
        "user_id":"4281941",
        "openid": "rxuCMrWjdxEZB0HBPzqSBlbzX3_zK8A1",
        "consumptions":[{"prop":"coin","num":1000}],
        "increases":[{"prop":"vip":"num":1}]
    
        
}
```

#### 返回示例

```json
{
    "code": 0 
    "data":{
     
    } 
}
```

### 响应要求

| <strong>字段</strong> | <strong>类型</strong> | <strong>说明</strong> |
| --- | --- | --- |
| code | Number | 0 成功 |
| msg | String | 错误信息 |
| data | Object | 需要返回数据时放到此字段 |
