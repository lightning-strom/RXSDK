# 概要

目前有的游戏类型为一个 openid 对应多个区服，每个个区服对应多个角色，为了更好的支持数据分析，望舒和大数据支持区服和角色的接入。

## 大数据用户属性现状：

* 望舒 openid 为唯一标识
* 不支持区服角色更新
* 只支持望舒 openid 维度的用户属性更新

![image.png](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1756892244684.png)

## 大数据用户属性支持区服角色后：

* 望舒 openid、区服、角色为唯一标识
* 支持望舒 openid、区服、角色多维度更新
* 用户属性包含望舒 openid 和区服角色维度的属性两份数据
* 根据用户属性划分的类型进行关联：公共用户属性，区服用户属性
* 公共用户属性：通行证产生的属性，例如，注册时间，实名认证信息等；
* 区服用户属性：游戏行为产生的属性，例如，游戏币等。
* 后台默认划分类型，后续支持用户自定义类型。

![image.png](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1756892256135.png)

2. 大数据分析模型逻辑

## 分析模型现状：

* 事件数据匹配用户属性时，以望舒 openid 为唯一标识匹配

## 分析模型支持区服角色后：

* 事件数据匹配用户属性时，根据用户属性划分的类型进行匹配：公共用户属性，区服用户属性
* 公共用户属性自动以望舒 openid 进行匹配(自动限制区服和角色为空)
* 区服用户属性自动以望舒 openid、区服、角色进行匹配

```
-- 公共用户属性
left join ods_event_user u 
on a.`#distinct_id` = u.`#distinct_id` 
and u.`#rx_region_tag` = ''
and u.`#role_id` = ''
-- 区服角色用户属性
left join ods_event_u ser uu 
on a.`#distinct_id` = uu.`#distinct_id` 
and ifnull(a.`rx_region_tag`,'') = uu.`#rx_region_tag`
and ifnull(a.`#role_id`,'') = uu.`#role_id`
```

3. 数据上报

## 事件属性：除通行证预置事件外，其余游戏内事件均需要上报固定标识的区服和角色

| 事件属性 | 显示名 | 数据类型 | 备注 |
| ---- | --- | ---- | --- |
| rx\_region\_tag | 区域标识(区服) | 文本 | 上报到事件数据的properties中，注意不带# |
| #role\_id | 角色 | 文本 | 上报到事件数据的properties中，注意带# |

## 业务支持区服操作

* 1、望舒将项目配置为区服模式，创建\_order\_publish topic
* 2、使用的 sdk 升级支持区服模式版本以上
* 3、所有服务端接口请求头增加ruixue-region、ruixue-cp-role-id

## 用户获取区服

如果当前游戏需要望舒下发区服，需要在版本发布-登录配置 配置具体区服信息，然后在安装包关联具体的登录配置，由版本检查接口下发具体的信息。
![image.png](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1761529340060.png)

[望舒通过版本检查接口下发服务配置](/docs/v3.5/版本检查/功能介绍)

```
{
  "login_config":[
      {
         "login_host":"",// 登录地址
         "login_name":"",// 名称
         "ext_param":"",// 扩展参数
         "region_tag":"",// 区服标签

  ]
}
```
