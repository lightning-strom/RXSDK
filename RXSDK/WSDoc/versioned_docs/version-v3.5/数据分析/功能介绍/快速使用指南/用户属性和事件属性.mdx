# 用户属性和事件属性

:::tip
**事件属性还是用户属性？**
一般情况下，Event 都是在用户产生某个有意义行为时上报的。
因此事件属性除了与该事件相关的属性外，还能够反映用户在进行该行为时的状态；而用户属性则只表示用户最新的状态。
例如同样表示会员等级的字段，事件属性中的等级表示用户发生该行为时的会员等级，而用户属性的等级则是用户现在的会员等级。
:::

## 哪些属性应该作为事件属性？

事件属性是每种事件所独有的属性，在上传某个事件之前需要 [埋点方案](/docs/v3.5/数据分析/功能介绍/快速使用指南/用户属性和事件属性)。

如何设置事件属性，则需要在项目理解阶段整理好事件列表，然后根据分析需求以及埋点触发的条件进行设置。

事件属性的名称，建议只使用英文大写、英文小写以及下划线进行标识，并且名称最好是有意义的，请勿使用中文命名。

如果有在不同事件中存在意义相同的属性，比如充值时渠道 ID 和购买道具时的渠道 ID，就可以设置为同一属性名，其作用相当于合并属性。

大数据平台支持的属性值类型有数值、文本、时间、布尔、列表。为了使用上的方便，对于需要了解具体含义的属性值，显示名建议使用中文赋值。

## 哪些属性应该作为用户属性？

用户属性表示的是用户的不变的属性以及最新状态。

我们建议将下列五种属性设置为用户属性：

（1）**user_setonce**：固定属性，初始化用户属性；根据数据中的用户 ID 确定进行操作的用户，再根据 properties 中的属性，对未赋值（为空）的属性进行设置，如果该用户的某需要设置的属性已经有值，则不会进行覆盖，如果某个属性不存在则新建该属性。

（2）**user_set**：最新状态，覆盖用户属性；根据数据中的用户 ID 确定进行操作的用户，再根据 properties 中的属性，覆盖所有属性，如果某个属性不存在则新建该属性，根据时间字段更新。

（3）**user_add**：累计值，累加用户属性，根据数据中的用户 ID 确定进行操作的用户，再根据 properties 中的属性，对数值型的属性进行累加操作，如果传入负值相当于原属性值减去传入值，如果该用户的某需要设置的属性未赋值（为空），则会默认设置为 0 后再进行累加操作，如果该属性不存在则新建该属性。（value 只支持数值类型，其他类型置空）

（4）**user_min**：历史最小值用户属性，根据数据中的用户 ID 确定进行操作的用户，再根据 properties 中的属性，对属性进行取历史最小值操作。

（5）**user_max**：历史最大值用户属性，根据数据中的用户 ID 确定进行操作的用户，再根据 properties 中的属性，对属性进行历史最大值操作。
