通常情况下，接入平台需要三个步骤：首先根据业务需求的整理，梳理出数据采集、埋点方案；然后，由研发人员根据埋点方案完成数据接入工作；最后是验证数据接入正确性。该接入流程如下图所示：

在数据接入之前，了解大数据平台的基础知识是非常重要的。本篇文档将会对必要的接入相关知识做一个整体的介绍，同时也会列出当您希望进一步了解相关内容的时候，如何获取帮助。

本文的目标读者是所有与接入相关的同事，包括业务人员、研发人员、测试人员等。

## 一、概述

望舒大数据平台提供了全端的数据接入方案，主要接入方式包括：[iOS SDK](/docs/v3.5/数据分析/功能介绍/产品说明) 、 [Android SDK](/docs/v3.5/数据分析/功能介绍/产品说明)、[JavaScript SDK](/docs/v3.5/数据分析/功能介绍/产品说明)、[Go SDK](/docs/v3.5/数据分析/功能介绍/产品说明)、[服务端 API](/docs/v3.5/数据分析/功能介绍/产品说明)；

- 客户端 SDK：[iOS SDK](/docs/v3.5/数据分析/功能介绍/产品说明) 、 [Android SDK](/docs/v3.5/数据分析/功能介绍/产品说明) 可以采集到设备信息，以及不与服务器通信的用户行为数据，简单易用
- 服务端 SDK：[Go SDK](/docs/v3.5/数据分析/功能介绍/产品说明) 采集内容更加精准，适合采集核心业务数据

针对一般应用和 Web 开发，我们提供了：

- [JavaScript SDK](/docs/v3.5/数据分析/功能介绍/产品说明)
- [服务端 API](/docs/v3.5/数据分析/功能介绍/产品说明)

对于服务端采集方案，我们推荐使用 [Go SDK](/docs/v3.5/数据分析/功能介绍/产品说明) 的方案。该方案在数据导入的稳定性、实时性、和效率方面都有比较好的表现。

在设计数据采集方案的时候，可以根据您业务的情况，选择适合您产品技术架构和业务需求的解决方案。如果对采集方案有疑问，可以在支持群里咨询我们技术支持同事。

## 二、基础知识

### 2.1  平台数据模型

在进行数据接入之前，首先我们需要理解大数据平台中的数据是什么。

数据采集埋点方案的设计实际上就是根据业务分析的目标确定采集哪些用户行为事件的过程。例如，如果要分析用户充值情况，要采集的可能是用户支付行为数据。用户行为数据可以分解为：谁 (WHO)，什么时候 (WHEN)，在哪里 (WHERE)，以什么方式 (HOW)，进行了充值行为 (WHAT)，如下图所示：

用户行为数据在大数据平台中会被组织成用户相关数据和事件相关数据，并分别存入用户表和事件表中。用户数据主要用于描述用户的状态和不会经常发生变化的属性。事件数据用于描述与具体行为事件相关的信息。

在数据采集方案中，您需要确定在什么时机需要触发用户数据的上报，在什么时机需要触发事件的上报。关于用户数据和事件数据的进一步了解，可以参考：[用户属性和事件属性](/docs/v3.5/数据分析/功能介绍/准备工作/接入前的准备工作) 。

在我们的所有数据接入指南中，都会分别介绍上报事件数据和用户数据的方法。

### 2.2 用户识别规则

对于每一条用户数据或者事件数据，都需要明确该数据是属于哪一个用户。在没有账号体系的场景中，可以使用与设备相关的 ID 来唯一标识用户。但是对于有账号体系中的场景中，一个用户可能在多个设备中产生数据，在分析中有必要将用户在多个端的数据结合起来分析，与设备相关的唯一 ID 就不适用了。

为了处理以上两种场景，在数据接入的过程中，需要结合两个用户 ID 来标识用户：

- 登录 ID（#distinct_id）：用户的登录 ID（rxopenid）。

  - 用户在登录状态下的标识，用来标识用户在登录后的数据，#distinct_id 字段上报时填写望舒 OpenID 字段数据。通过登录 ID 可以将多个设备中的数据关联起来。
- 设备 ID（#devicecode）：用户在未登录状态下的 ID。

  - 用户在未登录状态下的标识，用来识别用户在登录前或者游戏外的数据，比如说注册前数据、广告数据等。

在大数据平台标识一个用户的唯一 ID 为登录 ID（#distinct_id 字段），也就是望舒 OpenID。当接收到数据时，我们会根据指定的[用户识别规则](/docs/v3.5/数据分析/功能介绍/产品说明) ，来创建一个新用户，或者将数据绑定到一个已有用户上。

[用户识别规则](/docs/v3.5/数据分析/功能介绍/产品说明)  是非常重要的内容，如果没有正确设置登录 ID，可能会造成数据绑定到错误的用户上，影响分析效果，在接入之前请务必仔细了解该规则。

### 2.3 数据格式

无论通过哪一种方式接入数据，在发送到数据接收端的时候都使用统一的数据格式，和相同的数据限制。

如果您通过 SDK 对接数据，只需要调用对应的接口，SDK 会将数据整理成需要的数据格式进行上报；如果您通过 [服务端 API](/docs/v3.5/数据分析/功能介绍/产品说明) 接入数据，则需要整理好数据格式，然后上报。

关于数据格式，需要特别注意命名规则和数据类型：

- 命名规则：事件名和属性名都只能包含字母、数字、和下划线 _，以字母开头，不能超过 60 个字符

::: warning
属性名对大小写不敏感；事件名对大小写敏感；
:::
- 属性值数据类型：

::: warning
在大数据平台，属性值的类型会根据第一次收到该属性值的类型确定，后续如果数据中某个属性的值的类型与此前确定的类型不符，该属性将被丢弃；
:::

在大数据平您可能会注意到某些属性名是以 # 开头的，此类属性为预置属性。预置属性不需要特别设置，SDK 会默认采集。具体可以参考：[预置事件和预置属性](/docs/v3.5/数据分析/功能介绍/产品说明) 。

您需要特别注意的是，当数据格式或者数据类型没有正确设置的时候，数据无法入库。因此在接入阶段和接入之后，你可能需要通过埋点管理模块来检验或者观察数据上报的正确性，并对出现的问题及时修正。

## 三、接入必备信息

在正式由研发进行数据接入之前，需要确保以下信息已经准备好：

1. 项目 CPID：在望舒管理平台部署的时候会生成项目的 CPID，接入之前项目 CPID 会同步给项目组。
2. 数据采集方案，要包括：

   - 数据接入的方式：客户端 SDK、服务端 SDK、 RESTful API 接口或者几种方案结合的方式。详细内容可参考 [iOS SDK](/docs/v3.5/数据分析/功能介绍/产品说明) 、 [Android SDK](/docs/v3.5/数据分析/功能介绍/产品说明)、[JavaScript SDK](/docs/v3.5/数据分析/功能介绍/产品说明)、[Go SDK](/docs/v3.5/数据分析/功能介绍/产品说明)、[服务端 API](/docs/v3.5/数据分析/功能介绍/产品说明)；

恭喜您完成了接入前准备文档的阅读。接下来，您就可以根据选定的接入方式，参考对应的接入指南文档，开始进行数据接入了。
