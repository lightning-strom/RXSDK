:::warning

### 常见问题及处理

**1、检查不到产品包版本**
查看请求脚本类型是否和后台一致， 终端设备是否加入了测试 ip， 版本状态是否为自测、测试中或已发布, 客户端是否使用了没有的版本号，并且该产品包也没有一个大于客户端版本的已发布大版本更新（或加入测试 ip 的测试版本）

**2、检查不到大厅组件版本**
大厅组件版本是否关联了此产品包， 后台填写的产品包的主模块是否为此大厅组件

**3、检查不到子游戏版本**
请求的地区是否和游戏的地区一致， 产品包是否关联了游戏， 请求参数 games 里是否有此游戏

**4、 检查不到活动版本**
产品包是否关联了活动、请求参数 activities 里是否有此游戏, 检查是测试 ip 填写的否是最后一个版本
检查顺序： 已发布包中最后版本 => 待发布包中最后版本 => 测试包中最后版本

**5、返回值中有 res 字段**
res 字段是为兼容 js 而返回的， 全部升级后会废弃掉

### 定义及解释

> 1、参数 `type`, 脚本类型默认 js 可选值 `lua(.lua)` 、 `js(.json)` 、`u3d(.json)`
> 2、约定产品包版本号为 4 段式，其中前 3 段为产品包版本号， 第 4 段为大厅组件版本号， 大厅组件、游戏和活动版本号为数字
> 3、接口成功时返回的格式为 `{"code":0, "data":"版本信息 json 或 lua 格式字符串"}`， 失败时返回的格式为 `{"code":150000, "msg":"错误信息 code 不固定"}`
> 4、状态 自测中，待测试， 测试中，已锁定待发布，待最终审核，等待发布中 状态下，指定的 ip 可以被检查到， 已发布状态所有ip都可检查到
> 5、测试和预发布版本只检测指定IP的最新版本的， 比如有状态为自测中的版本 1 和版本 2，如果配置的IP相同，则只能返回版本2
> 6、约定版本号第二位是大版本更新， 第三位是热更，例如 3.7.0 就不会更新到 3.6.1 的热更包， 当 3.7.0 在审核时， 可以为线上 3.6.x 热更， 不能跳过更新的包可以选择为里程碑， 客户端可以设置审核中不更新，避免更新 3.7.0 的包，跨大版本只能整包更新
> 7、热更包格式为.zip , 上传后会自动解压并且地址会变为目录， 客户端可以通过地址+文件名的方式直接访问压缩包内的文件
> 8、产品包为小游戏和 h5 时，返回客户端指定版本的信息，产品包可检查到最近 8 个历史版本， 大厅组件、子游戏和活动可检查到最近 10 个历史版本， 客户端包太旧时会返回最新版本
> 9、app,h5 和 u3d 小游戏返回大厅组件，游戏和活动版本， 海外新增请求参数 vc， 如果不为 1 时不下发大厅组件，非海外的苹果审核模式不返回大厅组件、游戏和活动版本
> 10、如果版本关联中产品包版本配置了模块版本， 则只能返回指定的模块版本中的最新版本
