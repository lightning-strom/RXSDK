## 登录注册

### 注册

> **POST：** `/v1/passport/account/register`
>
> **认证方式：无**

#### CURL示例

```bash
curl --location --request POST '{{接口域名}}/v1/passport/account/register' \
--header 'ruixue-language: {{语言}}' \
--header 'ruixue-cpid: {{CPID}}' \
--header 'ruixue-productid: {{产品标识}}' \
--header 'ruixue-cpts: {{时间戳}}' \
--header 'ruixue-traceid: {{TraceID}}' \
--header 'ruixue-cpsign: {{请求签名}}' \
--header 'ruixue-devicecode: {{设备码}}' \
--header 'ruixue-channelid: {{渠道标识}}' \
--header 'ruixue-platformid: {{平台标识}}'
-d '{"captcha_code":"0651","password":"xxxxx","username":"19877771111"}'
```

##### logindata加密规则

构造如下 json object 数据

| 字段 | 类型 | 是否必填 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| ext | String | 是 | 当前登录用户的 CP 方唯一标识，须为数值型的字符串，如 "100" |  |

如 `{"ext":"100"}`记这一 json object 数据的 utf8 编码为字节数组 A。

将字节数组 A 进行 padding ，使其为 16 字节的整数倍（补 1 至 16 个字节），其中最后一个字节为所补字节数对应的 byte 值。比如 json 数据本身有 13 个字节，则补充 3 个字节，其中最后一个字节是 0x03。得到字节数组 B。

使用 AES 算法（ CBC mode ）对字节数组 B 进行加密，使用对应产品包的 appkey 作为 key （望舒的 appkey 是 32 个字符的字符串，该字符串的 ASCII/utf8 编码的 32 字节内存结构即为 AES key ，因此使用的是 256 bits length 的 key ）， appkey 的前 16 字节作为 IV。得到一个新的字节数组 C。

将字节数组 C 转化为 base64 的字符串形式，作为 logindata 数据传递

##### login_openid解密

登录接口返回的 login_openid 信息是包含登录用户信息的加密字符串，使用对应产品包的 appkey 进行加密。为安全起见， CP 服务器不应使用客户端传递的明文 openid ，而应从客户端获取 login_openid。CP 服务器可以使用相应的 appkey 进行解密，获取包括登录用户的 openid 在内用户信息，作为登录用户的唯一标识。如果 CP 服务器使用 go 语言实现，可以使用 ruixuego sdk 对 login_openid 进行解密。参考 [ruixuego/examples/openid](https://github.com/ruixueyun/ruixuego/blob/master/examples/openid/main.go) 里面的例子。简单的说， CP 服务器在初始化的时候需要配置好各产品包（通过 productid ， channelid 关联）对应的 appkey ，然后在收到登录请求的时候，通过当前用户登录的 productid 和 channelid 信息找到关联的 appkey ，并用该 appkey 对客户端从望舒登录接口获取的 login_openid 进行解密，获取 明文 openid 信息。如果 CP 服务器使用其他语言实现，可以按照以下步骤对 login_openid 进行解密：

将 login_openid 进行 base64 解码，得到一个字节数组 A。

使用 AES 算法（ CBC mode ）对字节数组 A 进行解密，使用对应产品包的 appkey 作为 key （望舒的 appkey 是 32 个字符的字符串，该字符串的 ASCII/utf8 编码的 32 字节内存结构即为 AES key ，因此使用的是 256 bits length 的 key ）， appkey 的前 16 字节作为 IV。得到一个新的字节数组 B。

读取 B 的最后一个字节的值，应在 1 至 16 范围内，假设为 p。然后将 B 中末尾 p 个字节移除，得到新的字节数组 C。

字节数组 C 对应一个 utf8 编码的 json object ，其结构如下，将其进行 json 解析即可得到各字段信息

##### FieldsSign签名计算方法

将 sign_fields 指定字段的字段名及其值, 构造成 k1=v1&k2=v2 的 URL Query Params 形式, 其中 key 和 value 都经过必要的 URL 编码, 并根据 key 进行排序.

比如登录时传的 sign_fields 是, ["nickname",“avatar"], 而登录结果返回的信息是

```json
{
 "code": 0,
 "data": {
 "nickname": "strongman",
 "avatar": "https://th.strongman.com/th/id/head.png"
 ...
 }
}
```

则这一步骤将得到:

```groovy
avatar=https%3A%2F%2Fth.strongman.com%2Fth%2Fid%2Fhead.png&nickname=strongman1114cde09ebe42fd167510c727f57f72
```

在第一步构造的字符串后面直接拼接 CPKEY.

假设 CPKEY 是 1114cde09ebe42fd167510c727f57f72, 则这一步之后将得到:

```groovy
avatar=https%3A%2F%2Fth.strongman.com%2Fth%2Fid%2Fhead.png&nickname=strongman1114cde09ebe42fd167510c727f57f72
```

使用 sha1 算法对以上步骤构造的字符串计算 hash 值, 为 byte 数据. 再将此 byte 数据转为小写 16 进行形式, 得到 fields_sign.

这一步骤, 相当于 go 语言的如下代码:

```go
h := sha1.New()
h.Write(source)
sign := hex.EncodeToString(h.Sum(nil))
```

这段代码中, source 为经过上面 2 个步骤拼接得到的字符串. hex.EncodeToString 是将 sha1 得到的 []byte 类型的 hash 值, 转为为小写 16 进制的字符串.
