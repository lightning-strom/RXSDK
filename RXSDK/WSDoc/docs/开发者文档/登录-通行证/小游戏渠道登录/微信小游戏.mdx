## 登录

**启动路径参数注意事项**
:::tip
SDK 登录内部会从启动路径上获取参数，用于裂变和导量效果的数据分析，所以 CP 如果需要自定义分享需要拼接以下参数，分享参数来自 `getShareData` 接口，并且注意
除了 CP 自定义分享场景，不要使用以下参数！！！
:::

| **字段**    | **类型** | **备注**                                     |
| ----------- | -------- | -------------------------------------------- |
| type        | string   | rx                                           |
| user_source | string   | share ｜ guide ｜ transmits 
`share` 分享 `guide` 导量 `transmits` 自定义透传参数 |

> 分享相关字段

| **字段**             | **类型** | **备注**                                                            |
| -------------------- | -------- | ------------------------------------------------------------------- |
| landing_id           | string   | 广告推广来源信息                                                    |
| trigger_id           | string   | 埋点 ID                                                             |
| trigger_tag          | string   | 埋点唯一标识                                                        |
| trigger_type         | string   | 埋点类型                                                            |
| material_type        | string   | 分享素材类型                                                        |
| material_id          | string   | 分享素材类型                                                        |
| strategy_type        | string   | 策略类型                                                            |
| strategy_id          | string   | 策略唯一 ID                                                         |
| share_time           | string   | 分享时间                                                            |
| share_type           | string   | mini，游戏客户端自定义的分享类型                                    |
| inviter_region       | string   | 分享者所在地区编码                                                  |
| inviter_openid       | string   | 分享者的望舒 openid                                                 |
| inviter_productid    | string   | 分享者的产品 ID, 若为空, 则通行证通过 inviter_openid 获取关联信息   |
| inviter_channelid    | string   | 分享者的渠道 ID, 若为空, 则通行证通过 inviter_openid 获取关联信息   |
| inviter_subchannelid | string   | 分享者的子渠道 ID, 若为空, 则通行证通过 inviter_openid 获取关联信息 |

> 导量相关字段

| **字段**       | **类型** | **备注**              |
| -------------- | -------- | --------------------- |
| guide_platform | string   | 导量来源游戏平台      |
| guide_app      | string   | 导量来源游戏 app 标识 |

> transmits 字段

transmits 的数据为透传参数，规则需要满足user_source=transmits，除user_source=transmits外其他拼接的参数登录后将原样返回。
示例：`https://xxx.html?user_source=transmits&a=b&c=d`  
登录成功数据会新增字段`user_transmits:{"a":"b", "c":"d"}`

#### 参数说明

| **字段** | **类型**      | **是否必填** | **备注**     |
| ------------ | ----------------- | ---------------- | ---------------- |
| params   | ILogin        | 是           | 参数         |
| callback | IMethodParams | 是           | 回调函数集合 |

> ILogin 说明

| **字段**            | **类型**    | **是否必填** | **备注**                                                                                                                                                                                                                                          |
| ----------------------- | --------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| version         | string  | 是       | 是否拉起用户信息授权`base` 不拉起用户授权弹窗`normal` 拉起用户授权弹窗==💡：base 不会拉起用户授权所以不会传递加密值可能获得不到头像等数据，如果需要获取头像建议传递 normal==                                                      |
| method              | string      | 是           | 'minigame'，登录账号的类型                                                                                                                                                                                                                        |
| sign_fields         | string[]    | 否           | 指定对登录成功后返回的特定字段, 使用 CPKEY 计算签名. CP 服务器可重新计算签名并与登录返回的签名比对, 作为对望舒登录数据的校验. 支持的字段包括: nickname, avatar, openid, region, sex, age, 计算签名的逻辑会对指定字段进行排序, 此处传参与顺序无关. |
| reconnect_login | boolean | 否           | 否是【断线重连】，用于区分 SDK 内部是否需要处理登录后的逻辑（拉取商业化数据）`true` 不拉取商业化数据==SDK v3.5.0 版本开始支持==                                                                                                       |
| ext | Ext | 否           |扩展字段 |

> ext 结构说明

| **字段**     | **类型** | **是否必填** | **备注**                                                                                                                                             |
| ------------ | -------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| custom_ext        |    CustomExt  | 否           | 自定义透传参数 |

> CustomExt  结构说明

| **字段**     | **类型** | **是否必填** | **备注**                                                                                                                                             |
| ------------ | -------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| bigdata_ext |    object | 否           | 大数据预置事件透传参数  |

> IMethodParams 说明

| **字段** | **备注**                                                  |
| ------------ | ------------------------------------------------------------- |
| complete | (data) => voidcomplete：为函数且必传，data 为结果数据 |

#### 调用示例
```javascript
sdk.login(
  {
    version: "base",
    method: "minigame",
    ext: {
        custom_ext: {
          // 大数据预置事件透传参数
          bigdata_ext: {
            test: `test`
          }
        }
    }
  },
  {
    complete: (data) => {
      console.log(data);
    },
  }
);
```

### 修改用户信息
:::tip
由于部分项目的 **用户信息（头像、昵称、性别）** 没有直接使用**望舒通行证数据**，而是采用由**望舒通知游戏服务器同步方式**，在网络不好时可能会通知失败，导致游戏服务器存储的用户信息和望舒通行证信息不一致的情况。

每次调用修改用户信息时望舒会重新通知游戏服务器，为 **降低通知频率 减少服务器压力** 每次调用 **updateUserInfo** 时可将**旧用户信息传入 ext 中**，望舒对信息进行比对后将未修改的用户信息通知给游戏服务器，已修改的用户信息不会同步。
:::
