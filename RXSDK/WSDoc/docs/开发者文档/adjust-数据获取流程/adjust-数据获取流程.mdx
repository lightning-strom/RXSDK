### adjust 归因和国内媒体归因逻辑的区别

```plaintext
国内是由望舒归因， adjust 是自归因后通知望舒
```

### 接入准备

#### 客户端接入adjust的sdk

:::tip
请参考 [Adjust 官方文档](https://help.adjust.com/zh/developer/) 完成 SDK 接入。
:::

#### adjust 配置

##### 创建应用

![](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1740450004113.png)

红框处为应用 id ， 需要填写到望舒后台

##### 配置服务器回传

![](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1740450068290.png)

回传事件为客户端触发， 上报给 adjust ， adjust 再通过服务端回传给望舒， 目前支持（安装、 再归因、归因更新）， 由于 adjust 自判断的数据与望舒统计有差异， 望舒又上报了 rx_activation 作为补充， 回传 url 的域名为望舒 api 域名， 参数为望舒需要的变量

##### 配置回传事件

![](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1740452767716.png)

应用下需要配置回传事件，事件名需要添加前缀， 用于区分

#### 望舒后台配置应用

![](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1740453030752.png)

其中，注册事件和激活事件需要单独指定， 配置好应用后， 望舒会主动拉取 adjust 的事件

##### 映射

![](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1740453278739.png)

映射功能为望舒提供的事件上报规则引擎， 用来将望舒事件映射到 adjust 事件， 当望舒事件发生事， 望舒会将事件通知给**adjust**用于分析

##### 回流

![](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1740453124657.png)

开启回流后， adjust 回传的再归因中超过窗口期的为新注册

##### 上报媒体消耗

![](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1740453433607.png)

由于 adjust 无法主动获取到媒体的消耗， 所以需要将 adjust 中的消耗手动填到望舒后台， 用于**望舒大数据**测计算
