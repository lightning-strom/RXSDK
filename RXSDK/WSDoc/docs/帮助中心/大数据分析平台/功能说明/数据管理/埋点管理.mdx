# 埋点方案
```tip
本章节为您介绍如何上传埋点方案。
请注意重点关注文档中加粗、标注部分的描述。
```
```warning
注意：在正式通过接口上报数据前，必须在埋点管理中设置相关数据结构，上传数据依据设置好的结构才能正常入库。
```
## 埋点事件
### 添加埋点事件
1. 进入瑞雪平台首页，点击左侧菜单：**大数据分析平台**。
2. 在页面右上方，点击**数据管理 > 埋点管理 > 埋点方案**。
3. 在埋点方案页面点击右上方 **添加埋点 > 逐个添加 > 新增埋点事件**。
4. 输入信息后，点击页面下方【保存】按钮，保存已填写的信息。
![](https://guanwangyun.oss-cn-beijing.aliyuncs.com/document/dataAnalysis/VDZwbpnrtoCHO0xFVdlcRMZKnkc.png)
```tip
1. 带 * 的字段为必填字段。
2. 事件名和属性名只能是字母开头，可以包含数字和下划线的组合，其他特殊字符不能输入。事件名是标识事件的唯一标识，属性名是标识属性的唯一标识。
3. 属性名输入时，会自动建议已经存在的事件属性，选择后，自动带入所有的信息，并不可修改。
```
### 批量添加埋点事件
1. 进入瑞雪平台首页，点击左侧菜单【统计分析】-【大数据平台】
2. 在页面右上方，点击【数据管理】-【埋点管理】-【埋点方案】。
3. 在埋点方案页面点击右上方【添加埋点】-【批量上传】-【新增埋点事件】
4. 上传 xslx 文件后，系统解析内容完成上传。
![](https://guanwangyun.oss-cn-beijing.aliyuncs.com/document/dataAnalysis/DJombigSOoEoekxMZQrc3J1inxh.png)
```tip
1. 上传的文件需要遵循固定格式。建议先【下载模板】，然后在模板中编辑需要上传的内容。
2. 模板上传时会有以下限制逻辑：
  a. 已存在的事件，不会重复上传。
  b. 事件和属性信息格式不正确，不会上传。
  c. 已存在的事件属性，相关信息不会更新。
  d.  sheet 名称需要命名为：新增埋点事件。
  e. 事件名、属性名不能以#开头。即不允许上传预置事件、预置属性和系统属性。
```

```warning
1、已存在的事件，不会重复上传。
2、事件和属性信息格式不正确，不会上传。
3、已存在的事件属性，相关信息不会更新。
4、sheet名称需要命名为：新增埋点事件。
5、事件名、属性名不能以#开头。即不允许上传预置事件、预置属性和系统属性。
6、为保证埋点方案成功上传，请按照以下取值规则填写，并注意勿漏传标识为“必填”的字段
事件名：只能以字母开头，可包含字母、数字和下划线。不超过32个字符。
事件显示名：可输入任何字符。不超过32个字符。
事件说明：记录相关说明。不超过200个字符。
属性名：只能以字母开头，可包含字母、数字和下划线。不超过32个字符。
属性显示名：可输入任何字符。不超过32个字符。
属性类型：数值、字符串、时间、布尔、列表。
属性说明：记录相关说明。不超过200个字符。
```
### 编辑埋点事件
1. 进入瑞雪平台首页，点击左侧菜单：**大数据分析平台**。
2. 在页面右上方，点击**数据管理 > 埋点管理 > 埋点方案**。
3. 在埋点方案页面点击右上方 **添加埋点 > 逐个添加 > 新增埋点事件**。
4. 输入信息后，点击页面下方【保存】按钮，保存已填写的信息。
![](https://guanwangyun.oss-cn-beijing.aliyuncs.com/document/dataAnalysis/QypUbKI6romLllxYt9RcxqdFn5c.png)
```tip
1. 带 * 的字段为必填字段。
2. 事件名字段不能修改。
3. 事件属性只能新增或删除，不能修改信息。
```
### 删除埋点事件
1. 进入瑞雪平台首页，点击左侧菜单：**大数据分析平台**。
2. 在页面右上方，点击**数据管理 > 埋点管理 > 埋点方案**。
3. 在埋点方案页面，点击 **埋点事件 > 删除**。
4. 二次确认后删除该埋点事件。
```tip
如果该事件已经被用于看板展示，则不可操作删除。
```

## 公共属性
```tip
公共属性是为简化用户操作、减少事件属性重复添加，而抽象出来的属性概念。
```
### 如何创建公共属性
创建公共属性主要分为 3 个步骤：
1、创建分类
2、创建公共属性
3、分类关联事件
#### 创建分类

#### 创建公共属性
![](https://guanwangyun.oss-cn-beijing.aliyuncs.com/share/serverAccess/0002.gif)
#### 分类关联事件
![](https://guanwangyun.oss-cn-beijing.aliyuncs.com/share/serverAccess/0003.gif)
### 如何使用公共属性
![](https://guanwangyun.oss-cn-beijing.aliyuncs.com/share/serverAccess/0004.png)
- 公共属性上报时，如果是通过 SDK 上报，则只需要上报一次。
- 公共属性上报时，如果是通过 API 上报，则所有属性每次都需要上报。
### 特别注意
1、建立分类：事件可关联分类（1-1），属性可关联分类（1-N）。
2、事件和属性，根据分类产生关联。
3、事件分类变更，要解除原有分类属性，绑定新的分类属性。
4、属性分类变更，事件的分类属性也要变更。
5、属性绑定分类后，对应分类事件中如果存在该自定义属性，则自动变更为公共属性。
| 场景  | 结果描述 |
| --- | --- |
| **前提：**<br/>1. 事件 E1 绑定了分类 C1 。<br/>2. 分类 C1 下有公共属性 A1 。<br/>3. 分类 C2 下有公共属性 A2 。<br/> <br/>**操作：**<br/>事件 E1 从绑定分类 C1 ，改为绑定 C2 。 | 事件 E1 下的公共属性从 A1 变更为 A2 |
| **前提：**<br/>1. 事件 E1 绑定了分类 C1 。<br/>2. 分类 C1 下有公共属性 A1 。<br/> <br/>**操作：**<br/>事件 E1 解除绑定分类 C1 。 | 事件 E1 下的公共属性不再包含 A1 |
| **前提：**<br/>1. 事件 E1 下有自定义属性 A1。<br/> 2. 分类 C1 下有公共属性 A1 。<br/> <br/>**操作：**<br/>1. 事件 E1 绑定了分类 C1 。 <br/>2. 事件 E1 解除绑定分类 C1 。 | 1. 事件 E1 下的自定义属性A1 变成公共属性。<br/>2. 事件 E1 下的公共属性和自定义属性都不再包含 A1 。 |
| **前提：**<br/>1. 事件 E1 绑定了分类 C1 。  <br/>2. 分类 C1 下有公共属性 A1、A2 。<br/> <br/>**操作：**<br/>属性 A1 从绑定分类 C1 ，改为绑定 C2 或属性 A1 删除。 | 事件 E1 下的公共属性从 A1 、A2 变更为 A2 |
| **前提：**<br/>1. 事件 E1 和 E2 下包含自定义属性 A1 。 <br/>2. 分类 C1 下有添加公共属性 A1。<br/> <br/>**操作：**<br/>事件 E1 绑定分类 C1 ，事件 E2 未绑定 C1 。 | 事件 E1 下的自定义属性 A1 变更为公共属性。<br/>事件 E2 下的自定义属性 A1 仍然为自定义属性不变。 |
