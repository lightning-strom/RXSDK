## 一、功能介绍
分享调度策略的全局配置。可设置不同通路下分享失败的概率和提示语，设置不同渠道下不同用户类型可分享/看广告的次数和调度策略。

## 二、操作步骤
点击左侧 <strong>社交分享工具 > 分享广告调度</strong>，进入功能页面。
### 配置分享广告次数
登录系统后，左侧选择菜单 **社交分享工具 / 分享广告调度管理**  进入页面。需要优先配置 <strong>分享广告次数</strong>。
![image.png](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1768181010133.png)
### 有效&无效用户界定
可分别配置小游戏和 APP 的用户界定。初始都为有效用户。
对于小游戏来说，界定的方式主要是分享卡片累计一定次数后未拉新拉老则为无效用户，反之为有效用户。（若拉新/老成功，该用户的累积次数重新记录。）
对于 APP 来说，界定的方式是分享落地页累计一定次数后，访问次数小于规定次数则为无效用户，反之为有效用户。（若用户被定义为无效用户后，访问次数超过规定次数，会变为有效用户，并且重置累计分享次数和访问次数。）
### 分享失败概率&提示
根据开启的分享通路设置。配置分享失败概率及提示语。提示语支持多条（多条请用分号分隔），将随机返回失败提示语。
默认 <strong>全部通路</strong> 作为兜底规则，若配置了明确通路，则优先匹配。
```tip
例：
QQ 用户在分享时，优先匹配 QQ 渠道规则；微信用户未单独配置，则优先匹配全部通路规则。
```
<strong>次数限制</strong>
可根据渠道配置每日有效/无效用户分享、看广告的次数限制。
默认 <strong>全部渠道</strong> 作为兜底规则，若配置了明确渠道，则优先匹配。
此处次数为成功次数。上报成功后会扣掉对应用户的分享/广告次数。如果用户的广告和分享总限制次数全都用光了， 就直接下发错误。
如果配置的有效/无效用户的限制次数，该用户实际分享达到了判定有效/无效用户之间，重新定义了用户是有效/无效，那么将会重置限制次数并执行当前有效/无效用户的限制次数。
```tip
例：
华为渠道用户在分享时，优先匹配华为渠道的配置；应用渠道未单独配置，则匹配全部渠道的配置。
```
### 配置分享广告调度策略
:::tip
如果配置的埋点已经在广告管理中进行配置了，瑞雪会自动下发该埋点关联的广告ID。如果未配置则只下发看广告行为，需要自行处理逻辑。
:::
不同的用户类型配置不同的调度策略，比如对于有效用户多做分享，无效用户多看广告。

登录系统后，左侧选择菜单 **社交分享工具 / 分享广告调度管理**，选择 <strong>分享广告调度策略 tab</strong> 点击 <strong>新增</strong> 进入页面
![image.png](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1768181030257.png)
### 基本信息配置
填写调度策略的基本信息，选择要关联的埋点。
![](https://guanwangyun.oss-cn-beijing.aliyuncs.com/document/helpcenter/share/share_schd1.jpg)
```tip
每个埋点仅能与一个调度策略关联。
```
### 调度策略配置
点击 <strong>添加 </strong>按钮添加调度策略，需配置用户类型、充值金额、循环策略、循环次数等信息。其中有效用户、无效用户的界定在 <strong>分享广告次数 </strong>中设置。
![image.png](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1768181051257.png)
```tip
循环次数每日 0 点重置
```
### 充值金额命中规则举例

若配置多条策略，且金额间存在一定的区间，瑞雪将按照配置的金额拆成多段，精准匹配，如下。
| <strong>用户类型</strong><br/> | <strong>条件</strong><br/> | <strong>命中人群</strong><br/>                             |
| ----------------------------- | ------------------------- | ---------------------------------------------------------- |
| 有效用户<br/>                  | 充值金额 ≥1<br/>          | 命中 充值金额在此区间的人群（1 ≤ 充值金额 ＜1000）<br/>    |
| 有效用户<br/>                  | 充值金额 ≥1000<br/>       | 命中 充值金额在此区间的人群（1000 ≤ 充值金额 ＜3000）<br/> |
| 有效用户<br/>                  | 充值金额 ≥3000<br/>       | 命中 充值金额在此区间的人群（3000 ≤ 充值金额 ＜5000）<br/> |
| 有效用户<br/>                  | 充值金额 ≤5000<br/>       | 命中 充值金额在此区间的人群（5000 ≤ 充值金额 ）<br/>       |

### 设置循环策略

点击编辑按钮，设置循环策略。最少设置一个，最多可设置 5 个。设置项内容：分享 和 广告。
![image.png](https://haiqi-ruixue-test.oss-cn-beijing.aliyuncs.com/docOnline/image-1768181081166.png)
<strong>循环策略执行举例</strong>
A 用户配置的循环策略是：分享-> 广告-> 分享
- 当 A 用户登录后，获取当前策略为 <strong>分享</strong>
- A 用户操作分享且失败，则下次获取的策略还是 <strong>分享</strong>
  - A 用户操作分享且成功，则下次获取的策略是 <strong>广告</strong>
### 调度策略执行说明
调度策略执行过程中，会有以下几种场景

| <strong>调度策略</strong><br/>                    | <strong>执行规则</strong><br/> |
| ------------------------------------------------ | ----------------------------- |
| 用户分享次数达到上限，看广告次数未达到上限<br/>   | 瑞雪接口返回 看广告<br/>       |
| 用户看广告次数达到上限，户分享次数未达到上限<br/> | 瑞雪接口返回 分享<br/>         |
| 循环测试达到上限<br/>                             | 瑞雪接口不再返回策略<br/>      |
